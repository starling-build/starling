# amd-opus SPEC: sa1 90385e38 page-top heading space (the 12 pt on page 3 and the 2 pt on page 5 are one rule)

Property: the page header holds a square-wrapped picture (behindDoc, 0 to 106.5 pt from the paper top) that reaches
below the top margin, so every page's first body line is pushed down to 106.5 by WRAPPING, not by the header's extent.
amd-11's clean labs had no such float (hdrtop5 used a tall text header), which is why none reproduced it.

Evidence, all from Word's print of the real doc (line top = text top minus the font offset; heading offset 0.5 is
calibrated from v1, where the heading sits mid-page with its 12 pt):
- Page-top paragraphs with no space before (pages 2, 4, 6, 14): line top 106.5 = the picture's bottom.
- Page-top Ttulo1 headings (before 12): pages 3 and 10, previous paragraph after 0: line top 118.5 = 106.5 + 12.
  Pages 5, 13, 15, previous paragraph after 10: line top 108.6 = 106.5 + 2.
- Fits: line top = float bottom + max(0, before - previous paragraph's after). This also explains amd-11's
  "page 5 heading Word +1.95 vs ours": ours drops the whole 12 on every page.
- Correction to the earlier handoff: v1 (empty paragraph removed) does NOT keep 119.0; in Word's print the heading
  goes back to page 2 (602.5). v5's "plain" empty paragraph still has after 0, so it never tested this.

anchored to the header paragraph), body top margin 70.85. Per page: a heading (before 240, keepNext) followed by a
40-line keepLines block, and before it one filler paragraph whose space after is the variable, so each heading moves

before 24 with after 10. Files: empty <w:compat/> (as the real doc), compat 15, and a control without the picture.
