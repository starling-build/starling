# amd-opus RULE (puzzle 5): footnote-area breaks in sa1 3a00de51 and 58192c08 are two properties, not one

Short version: 3a00de51 is not a line-pitch drift. Our footnote separator line is 6 pt too short. 58192c08 has a different cause: the last paragraph's space after is charged against the notes.

## A. 3a00de51: the separator line takes the separator mark's run font (VERIFIED by a doc edit)
- The separator footnote (LibreOffice style) is `<w:p><w:pPr><w:rPr><w:sz 12/></w:rPr></w:pPr><w:r><w:separator/></w:r></w:p>`.
  The paragraph mark is 6 pt, but the separator run has no rPr, so it is Normal's Cambria 11. There is no pStyle, so Normal's pPr applies:
  line 247 auto, after 4, firstLine 710.
- The importer drops `w:separator` (no code reads it), so our separator line is sized by the 6 pt mark: 7.44 pt tall (6 pt x 1.172 x 247/240 + 0.2).
  Word sizes it at 11 pt: 13.47 pt. So Word's notes area is 6 pt taller, and "Se enfatiza" line 2 (bottom about 672.3) no longer fits under
  Word's separator top (about 667.4). With one line left (an orphan), the paragraph goes whole to page 4, as in Word.
- Test: the same docx with the separator mark set to sz 22 (which reproduces Word's 11 pt line) gives 80 -> 225 of 296 lines matched
  (mean |dy| 19.2 -> 0.24) on the fca97d2fe tip binary. Files are in /data/s/amd-opus/p5/ (t1.docx, t1.txt).
- Page 2 "0.35 pt drift" is mostly Word's 600 dpi position rounding (0.12 pt steps). Across page 2 we end 0.12 pt off Word.
  The camp lab pitch matches to 0.005 pt per line. Not a cause.
- Rule to implement (by property): a `w:separator` / `w:continuationSeparator` run counts as a character of its own run font
  when the line height is set (line = max(mark, separator run)), in footnote and endnote separators.
  Likely many LibreOffice-written docs (6 pt mark, bare run), so run the wide A/B.
- Also visible (draw only, no break effect): Word starts the rule at the separator paragraph's first-line indent (3a00de51: x 71.54 = margin + 35.5).
  Word draws the rule about 1.4 pt below the line middle, i.e. about 2.3-2.5 pt above the separator baseline (3a00de51 +1.36, 58192c08 +1.47).
  We centre it at x = margin.

## B. 58192c08: the space after of the last paragraph before the notes is charged (fits amd-10's lab; needs ONE lab to confirm)
- The separator there is Calibri 11, single, after 0, and the run size equals the mark. A does not apply, and our separator top equals Word's (622.27).
- "iv) Incluir" (TNR 12, 1.15, after 10 pt): its last line's box (with the hanging 1.15 extra) ends 1.2 pt above the separator,
  and its glyph bottom ends 3.3 pt above. amd-10's lab (word-win/): v0 (7 note lines) goes to page 6 and v1-v5 (one note line, about 12.2 pt, fewer) stay on page 5.
  So the reserve is between 1.2 and 13.4 pt. The paragraph's 10 pt space after is the only property in that range.
  The 1.15 extra is 2.07 pt, which still fits even if it were charged.
- ONE lab (from amd-10's v0, change only iv)'s w:spacing after): after = 10 / 4 / 2 / 1 / 0.
  Prediction: 10 and 4 go to page 6, 1 and 0 stay on page 5. 2 tells whether the free space counts from the line box (1.2: page 6) or from the glyph bottom (3.3: page 5).
  Add a v0 copy with after = 0 and the NEXT paragraph's before = 10, as a control (before is dropped at a page top, so it should stay on page 5).
