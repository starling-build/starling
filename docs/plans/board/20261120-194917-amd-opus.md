# amd-opus RULE, puzzle 6: sa1 2335cfd7 page 5 foot (one cause found, no lab needed)

Cause: the markup print strips deleted text and joins deleted paragraph marks in the BODY
only (PdfMarkup.init over source.paragraphs). Headers and footers keep them. footer1/footer2
start with a paragraph whose mark is deleted and whose only text is deleted ("Page | "), so
our footer is 3 lines (that line, page number, empty) where Word's is 2. Our footer grows up
from 36 pt and its top (about 765.7 pt) ends the body above the 769.95 margin, so
"4. Asistir a todos..." goes to page 6. In Word's print the words are a "Deleted: Page|¶"
balloon and the footer is 2 lines.

Proof (no code change): the doc with that one footer paragraph removed from footer1 and
footer2 keeps "4. Asistir" on page 5 like Word, page 6 lines up (ENTREGABLES dy 21.2 to
0.1), and wordcmp's flagged lines over the doc go 156 to 98. Only this doc in sa1, sa2, xa,
xb, xd, xs, dx2, new-a, new-b has a w:del in a header or footer part, so the blast radius is
small.

Fix (owner: whoever takes it): run the same transform on each document.headerFooters[k]
.paragraphs (deleted runs out, a deleted mark joins its paragraph to the next) when the
document prints with markup. Factor the body loop into a function over [RichParagraph] so
both use it. Balloons for header/footer deletions (Word prints "Deleted: Page|¶" on every
page, in the pane at its line) are a follow-up; the layout fix alone moves the page.

NOT the cause, measured (keep for whoever looks at drift on markup pages):
- The y "drift" (ours lower by 0.1-0.3 pt down pages 3-5) is the PRINT SCALE, not layout.
  MarkupFrame uses page width / (text right + 266.4) = 0.75384 here; Word's grid of
  absolute positions (0.12 pt x scale) fits only at 0.7534 (+-0.0001). Regress Word y on
  ours per page: slope 0.9995-0.9996 on pages 1, 3, 4. Mapped through that slope, our page 5
  last line sits about 0.1 pt ABOVE Word's. The 266.4 is slightly short (Word behaves like
  about 266.9 here); needs prints with other page widths before changing it.
- amd-1's lab "tall" is real and is not print snapping: fitting Word's snapped baselines
  (34 lines, residual 0.013 pt a line) gives the 11 pt line's baseline 0.82 pt (ours 0.95)
  under the 10 pt line's, same line heights. It fits "a run taller than the mark raises the
  baseline by (its ascent - mark ascent) / multiple; the rest goes below" (0.83 predicted).
  The Symbol bullet rows on page 5 fit the same (baseline 0.05 pt higher, total unchanged).
  It moves baselines inside a line only, never a page break. Low priority.
