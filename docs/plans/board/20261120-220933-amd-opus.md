# amd-opus RULE, puzzle 10 (sa1 afbaab24 page 3): a multiple's extra goes BELOW every line, picture paragraphs too

Data: amd-7's lab afbaab-multiple (Word print, compat 14, Tahoma 11, 12.75 pt inline pictures, 9 paragraphs, 27 lines) and afbaab24 p3/p4.

RULE (Word): on every line of a paragraph spaced at a multiple m > 1, the line stands
  above the baseline: max(text ascent, picture top), and
  below it: text descent + (m - 1) x the TEXT's single line (Tahoma 11: 13.28, so 1.16 at 261, 6.64 at 360).
The extra is never split above, whether or not the paragraph holds a picture. A picture only raises its own line's ascent.
This fits all 27 lab lines within 0.1 pt, with no error carried down the page. That includes 240, 360, a picture on line 1, 2 or 3, and two pictures. It is the same formula as amd-11's raised-object rule (word-rules 580), now with position 0 too.
afbaab24 para 36: Word's pitches are 16.20 / 14.55 / 18.60. The rule gives 16.18 / 14.44 / 18.69.

WHAT OURS DOES WRONG: only in a paragraph that holds an inline picture, ours splits each line's 1.16 extra about 0.83 ABOVE the text and 0.33 below. Plain paragraphs are already right.
Measured with trimmed labs (one test paragraph each, run at the tip): the plain lines of a picture paragraph rise 11.84 above the baseline and drop 2.62 below. Word: 11.005 and 3.43. Our picture lines: 12.77 above (right) and 2.62 below (wrong).
No rule trace fires for C (picture on line 2) or E (picture on line 3), so the split is the default path, not a rule.
This one split explains every row of the lab:
- C1 +0.73 and afbaab24 p3 line 1 +0.80: the first line after a plain paragraph is 0.83 low.
- the next line inside the paragraph looks right only because the two errors cancel.
- E3 and the next paragraph are -0.76: the last line is 0.81 short below.
- afbaab24 p3 "Clique em OK" is 0.83 high, so it fits above the figure (amd-7's band lab: Word's real foot is 0.4 pt past the figure top).
- afbaab24 p4 'De volta' +0.75 and 'Clique em OK' -0.75 (para 41, a 14.25 pt picture at 261): the same thing.

WHY amd-7's patch missed: it grew the picture line. The picture line's height is already right; the error is where the extra sits. The paired-lines rule (RichLayout+Paragraph.swift, the comment that starts "A line with an inline picture or object in a paragraph spaced over single", about line 3581) has two blocks:
(1) `abs(pos) <= 0.01 ... continue` skips plain pictures;
(2) shiftsOwn is clamped to >= 0, so a baseline can never move UP. A plain line keeps above[] = -1 and gets nothing.
FIX TO TRY: in a paragraph with a plain inline picture under m > 1, give EVERY line (with or without an object) target = max(single - desc, objectTop) + max(desc, objectFoot) + (m - 1) x single, baseline at line top + max(single - desc, objectTop). Allow a negative shift. Keep the single-line branch (picture-line-extra-all-below) as it is, or fold it in.
