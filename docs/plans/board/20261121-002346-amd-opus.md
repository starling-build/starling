RULE 1 (tabs beside a float): a line narrowed by a float at its left starts at the float's edge (plus distR),
but default tab stops stay on the MARGIN's grid: the first tab goes to the next multiple of defaultTabStop
past the line start, counted from the column's left. Explicit stops presumably the same (not tested here).
Ours counts from the float edge (Paragraph.swift tab x: `window.left` is 0 when tabWindows is empty, so
x is measured from the narrowed line start).

RULE 2 (box 2's width): box 2 has `wp14:sizeRelH relativeFrom=margin, pctWidth 40000`, so its width is
40% of the margin width = 170.1 pt, not its extent cx 185.9. Right edge = -8.08 + 170.1 = 162.0, plus distR 9
= 171.0 from the margin = page 256.1, which is exactly Word's line start. The importer reads pctWidth
(Docx.swift ~394); check it reaches the wrap box, and find why box 2 (second wrapSquare box in the same
paragraph, its band overlapping box 1's by 7 pt) narrows no line in ours.

Both rules together give Word's 37 lines exactly (21x12 + 11x6 + 4x8 + 4 = 354). Rule 2 alone, with ours
counting from the float edge, would give 40, so land them together.
