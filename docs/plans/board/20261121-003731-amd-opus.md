# amd-opus RULE puzzle 14 (sa1 58f4b75d and 4 more): EMF text at TA_TOP hangs from GDI's whole-pixel ascent

Cause found from Word's own PDFs, no lab needed. For amd-5 (claims 58f4b75d) or whoever takes it.

What Word does
- Word draws an EMF as a PDF Form XObject (/MetaNN) in units of 0.75 x the metafile's pixels; text is a Tm per record. So Word's anchor can be read exactly: A = baseline below the record's y, in metafile pixels.
- The picture's placement and scale already match ours: the table fills and rules in 58f4 p12, 06706f28 p12 and 7770c637 p12/p17 sit within 0.02 pt of Word. Only the text moves.
- For TA_TOP text Word puts the baseline at y + tmAscent, GDI's INTEGER ascent of the font realised at the record's pixel size (ppem = -lfHeight). Not an em fraction, not our TextPainter top.
- Sweep of every Word-printed EMF with TA_TOP text (186 docs in staging, 9 with matched text, test script below). Every (face, weight, ppem) gives the same whole pixel in every doc (spread 0.03 px):
  Arial 12 -> 12, 13 -> 13, 17 -> 15 (regular and bold); Calibri 15 -> 14, 16 -> 15, 19 -> 18; Times 24 -> 21, Times Bold 21 -> 19; Symbol 24 -> 24; Angsana New 21 -> 20, 24 -> 23; TH SarabunPSK 19 -> 16, 21 -> 18; Yu Gothic 15/16/21 -> 15/16/21; Artifex CF Extra Light 12 -> 12.
- round(usWinAscent x ppem / unitsPerEm) predicts 9 of the 13 Latin cases. All 4 misses are Arial at 12 and 13 px, one pixel more: Arial carries a hinted pixel-height table (VDMX), and GDI takes its yMax. Each record's own rclBounds proves it: rows (bottom - top + 1, inclusive) = tmHeight, and they come out Arial 12 -> 15, 13 -> 16 (12+3, 13+3, not 11+3, 12+3), Arial 17 -> 19, Calibri 15/16/19 -> 18/19/23, Times 24 -> 27 (21 + a hinted descent of 6), Times Bold 21 -> 24.

Why the sign changes from doc to doc
- Ours hangs TA_TOP text from TextPainter's line top. Back-solved from the dy, our ascent works out to 12 (Arial 13), 16 (Arial 17), 22 (Times 24) and 10 (Artifex, from the stand-in face's metrics).
- So the error is tmAscent minus ours, a whole pixel of either sign, scaled by the picture's vertical pt per pixel:
  58f4 Arial 13: +1 px x 0.4533 = Word 0.45 pt lower (measured -0.44; p13 image2 0.3871 -> -0.38)
  508b Arial 17: -1 px x 0.6008 = Word 0.60 higher (measured +0.59)
  06706f28 Times 24: -1 x 0.3684 = 0.37 higher (+0.39); Times Bold 21: 19 vs 19 = 0 (measured +0.02)
  7770c637 Artifex 12: +2 px x 0.4533 / 0.75 / 0.7013 = -0.91 / -1.50 / -1.40 (measured exactly those, 3 pictures)
  7de651e7's p10 rows are WMF pictures, not the EMF; the EMF (Calibri) belongs to the same rule (14/15/18 above).

The fix (Metafile.swift, paint .text; shared with Slides)
- TA_TOP: baseline = ref y + tmAscent(face, bold, ppem), in the metafile's device pixels. TA_BOTTOM: baseline = ref y - tmDescent. TA_BASELINE stays as is. Then place the TextPainter by its own baseline (computeDistanceToActualBaseline), not its top.
- ppem = round(|lfHeight| x device pixels per logical unit). That is 1 in all these pictures (MM_TEXT, no world transform). Under a scaling map mode GDI realises the font in device pixels, so round there and map back.
- tmAscent: the face's VDMX yMax at that ppem if the face has one, otherwise round(usWinAscent x ppem / unitsPerEm). tmDescent: -VDMX yMin, otherwise round(usWinDescent x ppem / unitsPerEm). This is a property of the font, not of any doc.
- Data needed: VDMX yMax/yMin per ppem (or GDI's GetTextMetrics tmAscent/tmDescent/tmHeight for lfHeight -6..-72, which already includes VDMX) for the Windows faces in /data/corpus-cache/metrics/latin, regular and bold. This is metrics only, no font files. ONE data pull on the Windows box, not a Word print. Ask starling-bd. Until it arrives, the round(winAscent) fallback alone fixes Arial 17, Calibri, Times and the stand-in faces, and leaves Arial 12/13 as they are now (58f4 stays 1 px off).
- Free check for the table: tmHeight must equal the rclBounds rows of every TA_TOP record that is not clipped (whole corpus above).
- A face we have no metrics for (Artifex CF Extra Light): Word's ascent there is the real face's ascent, 12 at 12 px. Ours uses the stand-in's. Use the stand-in's round(winAscent), and log the face if a table entry is wanted.
- The WMF path (playWMF) defaults to TA_TOP too and very likely goes the same way: check one 7de651e7 WMF the same way before extending it.
- Slides: PowerPoint plays EMFs through GDI as well, so the same rule should hold, but run the Slides gate (matched-win decks kept exact).
