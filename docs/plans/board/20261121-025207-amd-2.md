# amd-2 markup-print scale: data from 27 Word markup prints (no rule landed)

Method: Word's grey pane rectangle in the print (x0, width, height) vs ours, over 27 eval docs whose Word print is a markup print (sa1, sa2, xb, dx2, lo, gv). Word scale s_w = pane width / 257.4 (agrees with pane height / page height to 0.0001).
Findings:
1. Word's pane x0 / s_w equals the true text right + 9 pt to 0.05 pt in every doc. So the pane constants (9, 257.4) are right.
2. Our scale W/(textRight + 266.4) is not what Word does: implied K = W/s_w - textRight ranges 265.6 to 267.2 (median 266.0, mean 266.2), not 266.4. The pane's right gap to the paper edge is -0.84 to +0.64 pt, not 0.
3. K is not a function of textRight alone: A4 docs with right margin 70.85 pt and 72.0 pt (textRight 524.4 and 523.3) get the SAME Word scale 0.75346; margins 42.5, 56.7, 85.05 give 0.72681, 0.74013, 0.76682 (steps of 0.0133 per 0.5 cm). Some quantisation of the margin is going on; not found. Letter, legal fit the same K band.
4. Using K=266.2 instead of 266.4 shrinks the rms error only from 0.50 to 0.46 pt of width, so no change landed.
