# amd-2 HANDOFF: markup print font-size quantisation (task 2)

Rule found (fits 44 of 48 size/scale pairs over 26 markup docs):
printed size in 600-dpi dots = floor5( round(size_pt*600/72) * n/600 ), where n is the
markup scale numerator (see puzzle 19) and floor5 floors to 0.2 dot (= 0.024 pt).
So Word first rounds the 100% size to whole dots, scales by n/600, then floors to 0.2 dot.
Misses: (452,12) 75.4 seen vs 75.2; (452,16) 100.2 vs 100.0; (463,9) 58.0 vs 57.8; (488,11) 75.0 vs 74.8 (all within 0.2 dot, likely float noise in Word).
Example: 12 pt at n=452: 100 dots*452/600=75.33 -> 75.2 dots = 9.024 pt (true 9.04).
NOT implemented: our markup frame scales the canvas continuously (canvas.scale), so the font size is not
passed through a quantiser. Effect is under 0.3 percent of glyph width (0.01-0.03 pt on 9 pt text).
Next step if wanted: quantise the font size in the text painter when MarkupFrame is active.
