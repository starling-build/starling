# OPEN amd-10 2026-11-21: per-character fallback face (Palatino Linotype, Ossetic Ae/ae)

PR 621 gives Palatino Linotype its own advances. It lacks U+04D4/04D5 (Ossetic
Ae/ae); Word draws them in Segoe UI (print of dx2 00f02cff embeds Palatino and
Segoe UI). The patch copies Segoe's two widths (regular 0.8604/0.8320, bold
0.9351/0.8281) into Palatino's "other" tables. That is a stopgap.

Proper rule (not built): a code point the run's face lacks is MEASURED AND DRAWN
in the fallback face Word uses for it (Cyrillic: Segoe UI). Today the width
path (RichLayout+Span.swift, the otherTable branch near "highFace") only
adjusts the measured width; the glyph is still drawn from the stand-in face.
Needs a per-face "lacks" test plus a fallback-face choice by script, then both
layout and paint reading it. Not small. Once built, delete the two merging(...)
entries in OfficeFontsPalatino.swift.
