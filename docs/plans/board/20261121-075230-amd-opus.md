## Rule (tbRl sections only; horizontal stays as it is)
Let s = base size, rs = ruby size, r = raise (hpsRaise/2), N = the face's own single line in em (`naturalHeight`: MS Mincho 1.3, Meiryo 1.99 in Word).
1. The ruby is a box N·rs tall, centred r from the base's centre (on the ruby side). The base line is a box N·s tall, centred on the base.
2. Overflow: o = max(0, r + N·rs/2 − N·s/2). This is how far the ruby box reaches past the base line box.
3. Off a grid: the column is the plain column + o, all of it added on the ruby side. The base stays where a plain column puts it. (This is lenovo-5's rule from rc-c, word-rules line 998.)
4. On a grid: column width = max(plain column at the paragraph's spacing, ceil((N·s + o)/pitch) pitches). Both boxes together are centred in the column. In other words, the base sits o/2 off the column centre, toward the NEXT column.
5. Every glyph in a column that holds a ruby moves with the base, plain characters included. This holds in one-column paragraphs AND in wrapped mixed paragraphs. Columns of the same paragraph that have no ruby stay plain.
6. The ruby's centre is the base centre + r. Word measures r − 0.08..0.14. Ours is r + 0.88 in every lab column, so find where the extra 0.9 comes from (see below).

## What is wrong in ours, and what to change
- `rubyLine` (RichLayout.swift, grid branch) computes the room over the text as `raise + ascent·rubySize − ascent·size`. That is the horizontal model: the ruby stands on a raised baseline. For MS Mincho it gives 4.94, where vertical needs o = 7.1; for Meiryo, 2.0 where it needs 3.5. Add a vertical branch with o = r + N·(rs − s)/2: height from rule 4, and the shift o/2 from rule 4. Gate it on the section being vertical, which means passing a flag in (rubyLine does not know today). lenovo-5's earlier wip used `raise + rubySize − size`. That matches Meiryo only because its N ≈ 2, and it regressed horizontal xd f42177d2 because it was not gated on vertical.
- Wrapped mixed paragraphs: `_mixedRubyRaise` returns 0 when the paragraph may wrap, and `movedHere` is 0 there too (RichLayout+Span.swift ~255, ~4934, ~5114). Word shifts each column that holds a ruby (rule 5). The shift has to be per line, not per paragraph: in _paintUpright, shift the column of every line that holds a ruby by o/2, and leave the plain lines of the same paragraph alone.
- Ruby offset: the ruby centre comes out r + 0.88 from the base centre in both rgrid (one column, movedHere = moved) and a_ruby (movedHere = 0). So the extra is not the move. Look at `(first.top + first.bottom)/2` in the vertical `_paintUprightRuby` call, which is the box centre rather than the drawn base glyph's centre. Base the ruby on the drawn base glyph centre + r.
- Today in a_ruby, the column of the first ruby line (薇 over ぜんまい, a ruby longer than its base) is about 1.9 pt wider than the later ruby column. After the change, check that every ruby column is ceil(...) pitches wide whatever the ruby's length.
