## Bug 1 (why your try changed nothing): the vshift number does not parse in wrapped paragraphs
`rubyColumnShift` (RichLayout+Layout.swift ~1448) reads the shift back out of `debugLabel` with `prefix(while: { $0 != " " })`. In a_ruby the ruby base style is copied again after the label is set (the ruby group's U+2060 joiners: `zeroWidth(current ?? kind)` in RichLayout+Span+StyledSblk0.swift, "word-ruby-group-holds-its-base"), so the label reads `...vruby-line vshift=71.09375).copyWith`, `Double("71.09375).copyWith")` is nil, and the shift is 0 in every column. rgrid's one-column paragraphs never got the extra copy, which is why it worked there.
- Verified: parsing with `prefix(while: { $0.isNumber || $0 == "." || $0 == "-" })` moves a_ruby's ruby columns by 3.55 (山 751.87 to 748.32, 春 698.47 to 694.91, rubies with them) and leaves rgrid byte-for-byte where #728 put it (746.05 / 678.40 ...).
- Better than the parse fix: carry the shift in a real field (or a side table keyed by run) instead of the debug label; `acrossC` and `_drawnBaseCentre` also read `debugLabel` as a face name.
