## Why ours is wrong
RichLayout+Paragraph.swift, tab loop (~line 1104): in a right-to-left paragraph, a tab with right-to-left letters before it on its
line is measured only on the paragraph's FIRST line (`if base != nil || lineStart != 0 { continue }`). On any wrapped line it is
skipped, so it keeps its natural width (a 14 pt space, 3.08). Ours: 18 tabs = 55.4 pt on line 3, the underscores fit after them,
one line less on page 4, pages 5-8 one line early. That is why removing `!style.rightToLeft` from the tab-run wrap rule did
nothing: the tabs never got widths, and that rule reads the probe's left-to-right edges, which mean nothing for Hebrew.

## The fix (rule by property: rightToLeft paragraph, tab after rtl letters on a wrapped line, text after the run)
A. Measure such tabs on wrapped lines too: pen before the tab = start indent (ownLeft) + width of the line's content from the
   line's start (the wrap offset w) to the tab, as the boxes' spread in the probe (same as the first-line rtlAt, without `lead`),
   with earlier tabs on that line counted at their stops (shift reset at the wrap, as now). Stops on the default grid from the
   column edge (ownLeft + pen, rounded up to the next 36), i.e. what the first-line path already does. Do not subtract `base`.
B. A tab whose stop lies past the line end (ownLeft + textWidth + 0.5), with non-space text after the run before the paragraph or
   line end: the line breaks BEFORE that tab, and its stops start again on the next line (from the column edge, first stop past
   the start indent). Mechanism like `afterTabWraps` + re-measure, but CHECK the final layout really breaks there: the engine may
   hang tabs as trailing white space and break after the run instead (then the underscores start line 4 at 523.55, Word 180).
   If it does, force the break at that offset.
