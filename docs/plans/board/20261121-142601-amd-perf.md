2. The log line "compiled: ..." lists at most 12 file names (head -12). So "0-12 files" is a cap, not a count.
3. Three cases:
   - Comment-only edit in one OfficeText file: 24 s total (swiftmodule unchanged, nothing downstream rebuilds).
   - Ordinary body edit in RichLayout+Paragraph.swift (the typical Word PR): 86-100 s. Timeline: ~1 s plan, emit-module ~11 s, ONE -O compile of that file 63 s (alone; 93 s with timing flags), link 4 s. The other changed files compile in parallel and finish earlier, so the biggest changed file is the critical path. Machine load barely matters here (one thread).
   - Any change that alters OfficeText's swiftmodule (new/changed declaration, even fileprivate): OfficeText 36 files + ALL 162 OfficeApp files recompile: 380 s. 12 files touched with a new decl each = 380 s.
4. Why the Paragraph compile is 63 s: RichLayout+Paragraph.swift:69 _layoutParagraphBody is ONE function of 5,270 lines (to line 5336). Type-checking it is 34 s (-debug-time-function-bodies), a few inner closures 4 s each; the rest is SIL/LLVM -O on one function, serial. Slow single expressions are small (<1 s each), so no type-checker hot spot to fix cheaply.
