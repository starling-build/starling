## Cause: spaces. Ours sets every space of a Faruma run at the stand-in's 0.22 em; Word at MV Boli's 0.4883 em.
The banner is the light-blue row (8 pt Faruma, "ޕޮއިންޓު ސްކޭލްއިން ... ވާނެއެވެ.", jc center, bidi). Measured per glyph on

matches MV Boli's table (RichLayout+ThaanaAdvances.swift) to 0.003 pt at 8 and 16 pt: space 3.924 at 8.04 pt, 7.788 at 16.

Ours (current main binary): our Thaana words are right (e.g. "ސްކޭލްއިން" 28.82 pt, Word 28.97), but each space is Caladea at
8 pt = 1.76 pt. The row has 28 spaces: 28 x 2.16 = 60.5 pt. Ours sets the whole text in 484.5 pt (54.7..539.2), and 484.5 + 60.5 = 545,

The same error is in the 16 pt title row (9 spaces, 4.3 pt short each).
Why the existing rules miss it: the face rule sends Thaana LETTERS (any run) and DIGITS (Thaana cs face) to MV Boli; the advance
rule scales a "word" only when it holds a Thaana letter. Spaces are their own tokens (and in this doc mostly their own runs,
ascii/hAnsi/cs = Faruma, no hint), so they keep the stand-in's width. ThaanaAdvances.table has 0x20 but nothing ever asks it.

## Word's rule (property): a missing face that the font table declares as Thaana is replaced WHOLE by MV Boli
Faruma's fontTable entry: w:sig usb2="00000100" = Unicode-range bit 72, Thaana. Word substitutes the missing face by MV Boli for
every character the run sets in it, any script slot: letters, spaces, digits, punctuation, Latin ("A1" in the box is MV Boli
'A' 12.44 at 18 pt = table). So:
1. A run whose resolved face for a character is a face missing on Windows with the Thaana bit in its w:sig (Faruma here) draws that
   character in MV Boli: MV Boli's line (already done for letters/digits) AND MV Boli's advance from ThaanaAdvances.table, spaces
   included. Where the table has no entry, keep the stand-in's width.
2. Do not widen spaces of Thaana words in a run whose face is a real Windows face (Times New Roman etc.): there only the letters
   fall back (lab case E settles it).
Implementation note: the cheapest hook is the per-token scaling in RichLayout+Span+StyledHelpers.swift (~line 603): also accept a
token with no Thaana letter when the run's face is such a face, and scale it to ThaanaAdvances.sum; make sure a token that is only
spaces reaches that function (if spaces are not tokens there, give them MV Boli's advance where the span is built).
