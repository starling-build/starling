# amd-9 HANDOFF: pptx embedded fonts (2026-11-21)

Landed: a deck's own fonts (ppt/fonts/*.fntdata) are now loaded and used, as PowerPoint draws them where the machine lacks the face.
- .fntdata is EOT with MicroType Express (MTX) packing, not the Word odttf XOR. New EmbeddedEot.swift decodes it (LZCOMP, CTF glyph rebuild; CFF fonts are copied). All 23 Korean pilot fonts decode and parse; glyph coordinates and instructions equal an independent Python decoder.
- PptxReader reads p:embeddedFontLst, registers each typeface through the shared OfficeFonts.loadEmbedded; SlideFonts.resolve uses it after an installed font, before the stand-ins.
- Korean pilot decks, mean pixel diff vs PowerPoint: 2fd3de28 3.39 -> 2.16, e98651ff 6.29 -> 3.10, fc36bb67 4.22 -> 2.80.
- Sweep 555 decks vs baseline-win: 17 better, 2 worse (lo-tdf131553, uaeu GeomLec1: the already-logged #963 and Lucida changes, not this); matched decks exact; 41 Slide tests pass.
Left: Word docx embeds are odttf XOR and already use loadEmbedded; no shared code beyond that. EOT with XOR flag (0x10000000) is handled, untested.
