# amd-opus SPEC (puzzle 7): Slides Arabic line pitch and digits, for amd-2 (rtl/6f97f2ee p12)

Measured on PowerPoint's own print (powerpoint-win, 16 rtl decks), not on ours.

## 1. The line is 1.2 em for EVERY Arabic face; the face's own height plays no part
- p12 (Sakkal Majalla Bold 54.02 pt, lnSpc 125%): baselines 160.68, 241.70, 322.73 | 406.73. In-paragraph pitch 81.02 and
  81.03 = 1.2 x 54.02 x 1.25 exactly. Sakkal's win/hhea is 1.3965 em; 1.3965 x 54 x 1.25 = 94.3 is OUR pitch.
- All 16 rtl prints, pitch / size by face: Sakkal 113 x 1.20, 62 x 1.44 (120%), 24 x 1.26, 11 x 1.50, 10 x 1.32 ...;
  Simplified Arabic (win 1.66 em) 44 of 56 at 1.20; Arabic Typesetting (win 1.14 em) titles 1.20 (27.96 pt -> 33.60);
  Arial, Times, Tahoma 1.2 x lnSpc. Every cluster is 1.2 x a line spacing. Same rule as amd-9's CJK lab (1.2 em at every face).
- CAUSE in our code: OfficeFonts.slidesArabicFace (Slides only; called from SlideFonts.face) copies Word's heights:
  Sakkal naturalHeight = boldHeight = 1.40, Simplified 1.658/1.663, Traditional 1.495, Arabic Typesetting 1.14, plus
  baseline/ownLineBaseline. A face naturalHeight beats theme.singleLineHeight (RichLayout.naturalLineHeight is only the
  fallback), so Sakkal lines step 1.40 x 1.25 x 54 = 94.5.
  TRAP that hid it: the run is BOLD, so boldHeight (still 1.40) wins over any naturalHeight you try. amd-2's
  naturalHeight trials changed only the regular cut. joinedHeight never mattered.
- FIX: in slidesArabicFace drop naturalHeight, boldHeight, baseline and ownLineBaseline for all four faces (Word keeps
  its own tables elsewhere; this function is Slides only). Give the baseline split through SlideFonts.ownDescentShare
  instead (winDescent / (winAscent + winDescent), metrics in /data/corpus-cache/metrics/rtl-full-20261121/):
  sakkal majalla and majalla ui 1050/2860; simplified arabic 979/3395 (bold 989/3405); traditional arabic 1025/3061
  (bold from its tsv); arabic typesetting 899/2334.
- CHECK, prediction from the existing rules: line 3 to line 4 crosses into paragraph 2, a one-line paragraph whose end
  mark is en-US Constantia (depth share 550/2500). The mixed-face rule (RichLayout+MixedFaces) with Sakkal 1050/2860 and
  the lnSpc foot rule (baselineShift) give 84.06; PowerPoint 84.00. In-paragraph lines must come out 81.03.
  First baseline 160.68 is the one number I could not close by hand (box centre 265.42, overflowing ctr anchor): compare
  ours after the fix before tuning anything.

## 2. Digits and brackets: the run's language tag decides, and the Sakkal face lacks its bold Latin widths
- PowerPoint draws "(", "4", ")", "2023" in Sakkal Majalla,Bold: "2023" 87.4 pt = 4 x 0.4053 x 54.02, "(" 15.5 = 0.2861 x 54.
  These are exactly OfficeFonts.sakkalLatinBoldAdvances (bold) / sakkalLatinAdvances (regular), already used by the Word path
  (OfficeFonts.swift ~4034).
- CAUSE: PptxReader already puts these digits in the Arabic piece (neutrals go with the letter before them). But
  slidesArabicFace is RichResolvedFace(family: Caladea) with no advances, so its digits take Caladea's widths. amd-2 set
  face.advances only: the run is bold, so boldAdvances (nil, measured Caladea Bold) still applied: 98 pt, not 87.
  FIX: Sakkal/Majalla UI: advances = sakkalLatinAdvances AND boldAdvances = sakkalLatinBoldAdvances. Same pattern for the
  other three faces where a Latin table exists (check the rtl-full tsv; add tables for the ones that lack them).
- Corpus survey (dig.py over all 16 rtl decks, ~600 digit runs): a run tagged ar-*/fa-* sets its digits, brackets and
  punctuation in the complex-script face EVEN WHEN THE RUN HOLDS NO LETTER (6f97f2ee "1:" 23 runs -> Sakkal; 2185f496
  "1- " -> Times; 898f62b7 -> Tahoma; 7854f160 "/49" fa-IR -> Arial = the theme's Arab font, not Georgia the Latin).
  A digit-only run tagged en-* goes to the Latin face (2185f496 "1" -> Calibri, 8c48d77a -> Lucida Sans Unicode).
  Our piece builder (PptxReader ~3855) gives a letterless run script nil = Latin face. FIX: a run with no letter takes
  the complex script of its lang (ar, fa, ur, ps, sd, ug -> Arab; he, yi -> Hebr; th -> Thai); a run with letters keeps
  today's rule. Rule by property (the lang tag), no face or doc names.
