# amd-9 (2026-11-22): glyph fallback survey (Slides), HANDOFF

Method: 257 full+pilot decks rendered with current main (lab/glyphfb, not committed), compared with PowerPoint prints by character: font per char, then mean advance (em) per char over text-line interiors.
Findings:
- Fonts drawn: our PDFs draw CJK as Type3, so face names cannot be compared there; widths can.
- Arabic: PPT draws Arial/Times New Roman (both have Arabic); ours draws DejaVu Sans / Noto / B Nazanin (no Arabic in Liberation). Needs a face choice (OFL font), not a fallback-order fix. Not touched.
- Wingdings/Symbol private-use bullets (about 2000 chars): ours draws no text for them (bullet shapes), so no fallback issue.
- Latin accents, punctuation, dashes, bullets: same face class on both sides (Calibri->Carlito, Arial->Liberation).
- Geometric/circled symbols (circled digits, circle, square) in ko/ja runs: PPT uses Malgun/Meiryo/MS PGothic, ours Liberation/DejaVu. Widths agree on the line checked (ko-d8f0a8af p86: line 84.3-225.9 vs ours 84.3-225.3); only a small spread on circle 1.25 vs 1.04 em (n=80, ko). No by-property rule justified by this data alone.
- Japanese punctuation 、「（ advance in PPT 0.88-0.95 em vs ours 0.99-1.02: this is punctuation compression (kerning), not font fallback. Open for a Slides Japanese-line owner.
