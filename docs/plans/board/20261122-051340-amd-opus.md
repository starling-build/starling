## How to read a print (this corrects the earlier survey)
PowerPoint's PDF names an embedded face it USED with a NUMBER: "1", "2,Bold", "3" (",Bold" = simulated bold). Samples prove it:
7854f160 B Nazanin text is font "3"/"1"; 9c2345ee Oswald text is "3"; 61813a3c "LESSON TWO" is "2,Bold"; 2ea63384 "Guia de orientação" is "1,Bold".
A face printed under its REAL name (Open Sans, Roboto, Raleway, Montserrat, Source Sans Pro, Noto Sans, Nunito Black, Nunito Light) did NOT come from the deck:
real-name faces print with simulated bold ("Raleway,Bold", "Open Sans,Bold", "Montserrat,Bold") even where the deck embeds a real bold file. These are almost certainly Office cloud fonts on the print box.
So b6dcd43a, 054ae4d7, 5a31aad7, a4b9e29e are not "embedded not used" cases: their faces came from the cloud.

## What separates used from not used (embedded file only, faces not installed and not cloud)
- Used (numbered font in print): every static TrueType-outline file (glyf, no fvar): Oswald, Tinos, Rambla, Paytone One, Spica Neue, Encode Sans, M PLUS 1p, B Nazanin/Zar/Titr, KoPub, Nanum, Helvetica Neue Light, Nunito Medium (static file, e3e0b3e0 "Actúo siempre" = font "3"), fsType 0 or 8, EOT flags 4 or 5. No counterexample.
- Not used: 96dcb877 Inter / Inter Medium / Inter SemiBold / League Spartan Black: all VARIABLE files (fvar+gvar; the four Inter parts are the same 347576-byte Inter variable font, default instance Regular, with only the EOT header renamed). Inter's internal family IS "Inter", the run typeface, so a name mismatch does not explain it. Printed Calibri.
- Not used: lo-multiplel Labil Grotesk 50: CFF outlines (OpenType/PostScript). Printed Calibri.
- No information: lo-tdf167214 Figtree (variable; print has no text in it), placeholder-* Krona One (the file is really Roboto; no Krona text printed).
- Ruled out as the separator (both groups have them): EOT fsType 0/8, EOT flags 4/5, embedTrueTypeFonts/saveSubsetFonts, Application, internal family name equal to the typeface (0a91d9aa Roboto's regular slot is "Roboto Medium" inside, ko-4f5289a9 나눔고딕 slots are Gulim/Arial inside, both still print numbered).

## Proposed rule (NOT yet proven: two decks, one per kind)
PowerPoint draws a run in an embedded face only if that embedded file is a static TrueType font (glyf outlines, no fvar). A variable file or a CFF file is ignored, and the run takes the ordinary missing-font path (as if nothing were embedded).
Separately: a face available as an Office cloud font is drawn from the cloud copy, and its bold is simulated unless the cloud has a bold.

Copy the ORIGINAL .fntdata bytes from the corpus decks (no re-encoding), listed in p:embeddedFontLst under the typeface given:

3 "Inter" regular (96dcb877 font1; variable, name matches)
4 "Figtree" regular (lo-tdf167214; variable, not Inter, checks it is the property not the file)
5 "League Spartan Black" bold, run b="1" (96dcb877 font5; variable)
6 "Labil Grotesk 50" regular (lo-multiplel; CFF)
7 "Rambla Twin" regular = Rambla's bytes again (static, typeface absent from the file's names: tests whether the name must match)
8 "Nunito Medium" italic, run i="1": its italic slot is the variable file (e3e0b3e0) while its regular slot is static: tests per-file, not per-family
Check every XML part with a namespace-aware parser. Readout per box: print font name (numbered = embedded used) AND a crop of the glyphs (variable Inter vs Calibri is obvious by eye).
Also ask starling-bd for the NAMES ONLY in the print box's Office cloud-font folder (%LOCALAPPDATA%\Microsoft\FontCache\4\CloudFonts): that settles the real-name group.
