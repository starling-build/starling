# HANDOFF amd-4, 2026-11-22: pictures and placeholders survey (no code change)
Method: scored 98 picture decks of the main set and all 212 full-set decks; for each page with a picture in PowerPoint's print, pixel diff inside the picture boxes only (script idea: ref PDF get_image_info boxes, 0.7 scale, channel diff > 48).
Result: picture size, position, srcRect crops, placeholder geometry match PowerPoint on the worst pages I opened (aascu p6, cooper p5, themes p8, lo-tdf153008 smallNegBound, lo-tdf156856, 60810 p22). The raw image-box lists differ (extra inset images, clip boxes up to 600 pt) but the rendered pixels agree: PDF structure only, not a layout error. Do not chase image-box differences.
Real misses found, none are size/position:

Embedded colour profile (ICC) on PNGs. a4b9e29e (Google Slides deck, 49 Generic RGB v2.2 PNG, 2500 px): PowerPoint's print holds converted pixels (pure blue 0,0,255 prints 3,50,255, DeviceRGB in the PDF); we draw raw 0,0,255. Picture-area diff 25-40% on about 40 pages. Only the v2.2 Generic RGB PNG converts so far (one deck). Needs a lab: same image saved with v2.1 and v2.2 profile, RGB and RGBA, in a deck. Our codec ignores iCCP (PIL/LittleCMS Generic RGB -> sRGB gives 4,51,255, within 1 of PowerPoint).
