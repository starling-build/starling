# SPEC amd-opus 2026-11-22 (puzzle 12, for amd-4): SmartArt text in an East Asian face takes Word's line, not PowerPoint's 1.2 em

Follows amd-9's handoff 20261122-140000-amd-9.md (b7d6faa9 p3, target3: PowerPoint 27.5 pt, ours 19.1).

## Rule (fits every multi-paragraph SmartArt node in the corpus)

Inside a SmartArt drawing (the dsp:sp text of ppt/diagrams/drawingN.xml), when the line's face is
an East Asian face (the faces whose plain-box line we already set at a flat 1.2 em, SlideFonts
ownDescentShare / the slides-cjk-lines rule), PowerPoint uses **Word's East Asian single line**:

- line h = floor(1.3 x (winAscent + winDescent)) / unitsPerEm em. This already exists as
  `OfficeFonts.wordEastAsianLine` (Meiryo UI 3381/2048 = 1.651, Meiryo 3993/2048 = 1.950,
  MS PGothic 332/256 = 1.297, DFKai-SB 1331/1024 = 1.300).
- baseline: the 0.3 extra is split evenly above and below, so the descent share is
  (winDescent/(winAscent+winDescent) + 0.15) / 1.3 (Meiryo UI 0.242, Meiryo 0.341).
- lnSpc percent multiplies h. A spcBef/spcAft **percent** is of h x size too (not 1.2 x size).
- Latin faces are unchanged: every Latin node in the corpus already matches within 0.4 pt.

The face decides, not the script: b7d6's "Data Science" is Latin text in Meiryo UI and takes the
Meiryo UI line. Plain text boxes stay as they are: amd-9's mixls/mixls2 copied these exact txBody
XMLs into plain boxes and PowerPoint drew them at our current 1.2 em, so this is SmartArt-only.
