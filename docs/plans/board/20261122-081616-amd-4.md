# amd-4 sa5c line pitch (2026-11-22), FIXED (PR 1498)

Lab sa5c p12 (SmartArt nodes, MS PGothic 24 pt bold, 90%): PowerPoint prints every node's lines 28.1 pt apart. Ours: 28.1 in node 2, 27.3 in nodes 1 and 3.

Found: it is the route the paragraph takes, not rounding or geometry.
- A paragraph whose end mark names a face spelled differently from the run (endParaRPr lang en-US) goes through the mixed-face path (RichLayout+MixedFaces) and prints 28.1.
- A paragraph with no end mark, or one with a ja-JP mark, has one piece name and takes the plain path: 27.3 (0.8 pt short).
- Proof: adding an en-US endParaRPr to every paragraph of the lab gives baselines 152.9/181.0, 221.1/249.2, 385.3/413.4 (PowerPoint 152.88/180.96, 220.68/248.78, 385.34/413.45). Adding ja-JP marks changes nothing.
- NOT the cause: baselineShift's exact branch (differs from the mixed model by 0.07 pt), txXfrm height, autofit, the text.
- Tried and failed: inheriting the last run's rPr as the mark (same ja-JP), letting the mixed-face guards pass on a named-line face (the run's piece name is the latin slot "calibri", so the check never matched).
- Fixed: in a diagram, a paragraph with no end mark of its own that ends in East Asian letters gets the East Asian face as its end mark (PptxReader), so it takes the mixed path like the en-US-mark case. Lab last-line baselines now 181.0 and 413.4 (PowerPoint 180.96, 413.45).
