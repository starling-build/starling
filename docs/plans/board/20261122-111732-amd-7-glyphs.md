# amd-7: PowerPoint print word widths against three width models (Tw Cen MT 9575f717, Aptos 7d895c94), 2026-11-22
Also: abbb4f78 p4 first-line 1 pt offset = Noto-vs-Arial face difference, waits on the user font decision (the 19.5 pt gap was a stale render).

Method: per word segment (non-space run followed by a space, same span) in the PRINT: width = next space origin - first glyph origin (PDF TJ drift cancels over a word). Models: sum of em advances (metrics: twcen-20261121, latin/Aptos_*) + GPOS/kern pairs (kern-latin/kern-zh tables), then
(a) plain 1/8 pt: ppem=round(size*8), advance round(em*ppem)/8, kern round(k*ppem)/8; (b) GDI hinted = (a) with the exceptions table (Aptos has none; Tw Cen MT has none at these ppem, so (b)=(a)); (c) unrounded em*size, kern*size.
Cells: mean |model - print| in pt, and number of segments within 0.03 pt. Script: /data/s/amd-7/glyph/seg.py.

Reading: for Tw Cen MT (16-24 pt) the unrounded widths are nearest the print at every size; 1/8 rounding is not supported. For Aptos, 1/8 rounding fits at 12 pt (ppem 96: 34 of 75 within 0.03 against 17) but unrounded fits at 18 and 54 pt. So whole-1/8 widths hold at small ppem only (here <=12 pt Aptos), not as a general rule. Caveats: the kern tables are ours (a wrong pair shows as error in all three models); residual 0.1-0.2 pt remains in every model, so something else (kern pairs missing, or TJ placement) is unmodelled. Aptos 54/18 rows are few segments.
