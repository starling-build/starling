# amd-2 HANDOFF: Arabic lines 1.7% too tall at 200% (picture,rtl)

Cause found: not a multiplier. An Arabic piece takes glyphs from whatever face has them; the engine sets a line to the tallest ascent plus deepest descent of the faces on it, so one line was 175.8 pt and the next 172.8 (ce81583c p1, 72 pt, 200%). PowerPoint's pitch is 172.7.
Fix: each Arabic-script piece with a height is held to its own style face's ascent/descent split (`_holdingArabicSplit`, called from `laidOut`).
Result: ce81583c p1 baselines 190.6/363.4 (PowerPoint 190.9/363.6); line match 95.0% to 98.3%; 8a5ae557 unchanged 88.8%. Unit tests 861/0.
Note: the earlier "flat 1.2 em" idea was already in effect; the closure was right.
