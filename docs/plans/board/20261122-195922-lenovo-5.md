# lenovo-5 HANDOFF: cases for the digit/punctuation font slot rule (for lenovo-3, who owns it)

Rule area: font of ASCII digits in runs whose latin/ea slot is +mj-ea / +mn-ea, over a theme whose ea face is empty.
Cases measured against PowerPoint prints (zh set):
1. 1892a5a76df6 p201: lang=en-US, no altLang, latin+ea both +mj-ea. PowerPoint prints Arial (bold digits 8.9 pt at 16 pt; Constantia, the theme's Latin face, is wrong).
2. 3c1f2c4d820b p7: lang=en-US altLang=zh-TW, latin+ea both +mn-ea, 8 pt digit after Chinese text. PowerPoint prints PMingLiU (theme Hant face), digit 4.0 pt; Arial's 4.4 pushed the digit onto its own line.
3. f2656c7a5436 and 2e721a5ae959 (+ ko-4f5289a9...): runs lang=en-US altLang=zh-TW with +mj-ea; they got worse (100 to 97.6, 96.4 to 93.6) when case 1 was applied to all non-Japanese runs, so altLang zh-TW must take the Hant face.
4. Already in code: lang or altLang ja-* takes the theme Jpan face (ja 24b61c69 p8, 5f748a0e p5).
Combined rule as I see it: empty theme ea face -> altLang/lang ja: Jpan face; altLang zh-TW/HK/MO: Hant face; otherwise Arial.
