# amd-3: wrap-fit room checked against amd-5's wrapfit counts (OPEN, no code)
Method: whole-pixel Calibri advances at ppem 29 (gdi-hinted table), greedy word wrap of the lab text, column px = trunc(15*w), room range that gives Excel's FIT line count per width (widths 7..20; widths 5,6 skipped, they break inside long words).
- col 105 px (w7): fit 7 lines needs room exactly 91 -> pad 14 px (0.867 x col).
- col 180: pad <= 14. col 240: pad <= 21. col 300: pad <= 24. Other widths loose.
- 52716 (col 160): room 148-149 -> pad 11-12. no_drawing_patriarch (col 419): room 397-400 -> pad 19-22.
- Rule "0.965 x col - 6" gives room 95 at col 105 (6 lines): does NOT reproduce the w7 7-line fit. Pad is not constant and not a fixed fraction: 14 @105, 11-12 @160, 19-22 @419.
- So the room is not a pure function of the column width with the glyph widths I use. Next suspects: per-char widths (hinted table vs real GDI at the row's font, '-' and capitals), or the lab row's 7-line fit coming from a different cause (first-row-tight assumption amd-5 flagged).
