# amd-perf HANDOFF: Sheets gate sweep, score reuse (2026-11-22)
The sweep was already parallel (books across cores, output sorted). The slowdown is CPU per book on the second set (about 6x heavier, long tail).
Change: sheets-sweep.py writes score-cache.tsv (PDF sha1 + rows, keyed to the scorer's own sha). With SHEETS_REUSE=DIR a book whose PDF is byte-identical takes the stored rows and skips pixel diff and line scoring. Heaviest books start first. sheets-gate.sh caches score-cache.tsv with the base and passes it to the PR sweep.
Check: 50 books, same binary twice: TSVs byte-identical, 51.7 s to 17.7 s (42 of 50 reused). A changed PDF is always rescored; a changed scorer invalidates the cache.
Render (about 2/3 of the time on set 2) is the remaining floor.
Guard: a stored score is used only when the PDF hash AND a hash of the scoring scripts (sheets-sweep.py, pdf-diff.py, docx-line-match.py) match; a scorer change rescores everything. Code is in PR 1947.
