# amd-opus SPEC 3 (puzzle 19): 47813 chart sheet + portrait worksheet (2026-11-22)

Read from prints that already exist (amd-5 b47r4/r5/r6, Excel 20527). No new print yet.

## What the existing prints already say
1. It is a SCALE change, not a default-row change. b47r6 f-heights (shifts) against h-all (does not), same stored heights:
   - stored 30 pt row: 30.4 pt against 31.4 pt; stored 100 pt row: 101.9 against 104.8. Ratio 0.972, the same as the default row 105/108 dots.
   - 20-character column B (d-cols against h-all): 127.9 pt against 127.2 pt, +0.55%. 127.2 pt is exactly 20 x 53 dots; 127.9 is 20 x 53.3.
   - Drawn glyph advances are identical in both (6.33/6.37 pt per digit). Only the grid moves.
2. One model fits both states (Verdana 10; screen font height 16 px, digit 8 px):
   - stored row = row px x H/16, default row = H + 3, with H = 105 dots normally and about 102 when shifted (40 px: 262.5 against 255; 133 px: 873 against 848; prints 261.7/253.3 and 873/849).
   - column = characters x D, with D = 53 normally and about 53.3 shifted.
   So Excel has taken the book font's height and digit width from a different device or mode. 102 is close to the plain font height at 600 dpi (101.3 unrounded); 105 is not explained yet. Baselines are read to 0.1 pt, so H shifted is 101.3 to 102.2; gridlines in the new lab give it to the dot.
3. "Printer DC re-created at the orientation change" is ruled out: b47r4 y prints every page portrait (chart sheet too, 17 pages 612x792) and still shifts.
4. "Portrait cancels / landscape cancels" is NOT yet proven to be about orientation. In every lab book that shifts the worksheet has NO pageSetup element at all (the original 47813 too); in every chart-sheet book that does not shift the worksheet carries `<pageSetup orientation="landscape"/>`. Orientation and "the worksheet has a page setup record" are confounded. My reading: a worksheet with no page setup of its own takes its device measure from a different place once the book holds a chart sheet (a chart sheet is sized to the printer page, so loading it makes Excel ask the printer early). To be tested, not assumed.

## Rule by property (provisional, do not land before the lab)
Book has a chart sheet AND the worksheet is [portrait | without its own page setup; lab books 1-2 decide]: lay the sheet out with the second measure (H2, D2) of the book font in place of (H, D). Everything scales: default rows H2+3, stored rows x H2/H, columns x D2/D. No face names; (H2, D2) must come from a formula over the font's metrics, which the four faces below give.

## Smallest confirming lab (10 books, one round)
All on amd-5's 60-row base, `<printOptions gridLines="1"/>` (exact dots from rulings), rows 5 and 8 stored 30 and 100 pt, column B 20 and C 80 characters. Chart sheet as in b47r6 a-control (no pageSetup, prints landscape).
1. Verdana 10, worksheet with explicit `<pageSetup orientation="portrait"/>`, plus chart sheet. Shifts: the property is portrait. Does not shift: the property is "no page setup record".
2. Verdana 10, TWO worksheets (first with no pageSetup, second landscape), plus chart sheet. Says whether the measure is per sheet or per book.
3-10. Calibri 11, Arial 10, Verdana 8, Verdana 12: each (a) worksheet with no pageSetup, plain and (b) the same plus chart sheet.
Read per book in dots at 600 dpi from the gridlines: default row, rows 5 and 8, widths of A, B, C. That gives (H, D) and (H2, D2) per face.
Then test: H2 = font height at 600 dpi for the point size (Verdana 8: 81, 12: 121.5 unrounded) and D2 against the digit at a fractional size; Calibri 11 "about 14.5 either way" should fall out as H = H2 with no face name. If H2/D2 fit no formula over four faces, that is the stop: write the table on the board, do not land a per-face table.

Traps for the builder: keep both sides of each pair identical except the chart sheet; d-cols moved column A's text 25 pt right against a-control (93.6 against 68.8) although A kept its default width, so adding `<cols>` changes A too; compare only within a pair.
