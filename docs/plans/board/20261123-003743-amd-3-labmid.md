# amd-3 confirming lab wrap-mid (predictions written before any print)

Folder /data/s/amd-3/starling/lab/wrap-mid/ (not in git): wrap-mid-{50,66,81,100}.xlsx (same 215 rows at print scales 50/66/81/100, folds in amd-2's margin-in-dots question from #1987), key.tsv (both models' per-row prediction), PREDICTIONS.md, gen.py.

Each row: cell "A B C D" (3 words that sum to Wp = column - pad whole pixels, then a short word D that never fits after C). Read from Excel's print which line C stands on: line 1 ("A B C" then D) or line 2 ("A B" / "C D").
Classes: narrow (i l t f r j), wide (m w d o q p b), mixed. Same Wp at every pad, but unrounded width Wu differs: narrow Wu < Wp, wide Wu > Wp.

Model W (merged fit, whole-pixel advances at 29 px/em Calibri 11, 27 Arial 10): C stays on line 1 iff Wp <= floor(column - max(11, 7.5 + 0.0145 x column)). The threshold pad is the same for narrow, wide and mixed; it is about 11 px at 77/147 and 11.85 at 300.
Model U (planner, unrounded): C stays on line 1 iff Wu <= column - c0 (Calibri 8.6, Arial 7.1). The threshold pad (in Wp terms) differs by class: narrow cells keep C on line 1 down to a much smaller pad (Wu is several px below Wp), wide cells wrap C at larger pads.
Per row both predictions are in key.tsv (columns predW, predU); the rows where they differ are the discriminating ones.
Also: 300 px Arial 10 column (models predicted opposite directions earlier).
Scales: the same sheet at print scale 50/66/81/100 % (amd-2's margin-in-dots question): if the break depends on the print scale, the C-on-line-1 set changes between the four prints.
Pass criterion: model W right if the observed line-1 set equals predW for all classes at 100 %; model U right if it equals predU.

Read-out: for each row, whether word C stands on line 1 or 2 in the Excel print; compare with predW and predU in key.tsv. Also hyphen-hang fix is PR #1989.
