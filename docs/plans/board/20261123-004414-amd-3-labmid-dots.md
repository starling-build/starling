# amd-3: wrap-mid lab, printer-dots model (CORRECTS 20261123-labmid-scored)

Correction: "unrounded, one constant" holds only at 100%. No single screen-pixel constant fits 81/66/50% (e.g. 81%: needs c0 > 9.6 and <= 8.4).

Better model, tested on all four prints (215 rows each, tool lab/wrap-mid/dots.py, copy in /data/s/amd-3/sh/dots.py):
Excel decides the wrap on the PRINT grid: ppem = round(size x 600/72 x scale), per-glyph advance rounded to whole dots, column = px x 600/192 x scale dots, wrap iff text width > column - M dots, one M per scale.
Rows right (rounded / unrounded-at-same-grid): 100%: 208/205, 81%: 210/201, 66%: 211/203, 50%: 190/182.
Best M dots: 24.5 (100%), 22 (81%), 17.5 (66%), 13.5 (50%) = about 7.8, 8.7, 8.5, 8.6 px x scale.
Calibri alone: 122/125, 124/125, 124/125, 125/125. Arial: 86/90, 86/90, 87/90, 65/90 (50% Arial is where it breaks; windows wide).
So the margin is a constant in print-scaled px (about 8.6 px x scale) and the width is measured on the print grid: this is amd-2's margin-in-dots idea plus grid rounding. The whole-pixel screen fit (merged) is the 100%-print-of-a-rounded-grid special case, not the rule.
