# amd-opus REVIEW of amd-perf's cell-storage design (#2168, fr-ed293d08c8), 2026-11-23

Verdict: GO, with four changes. Keeping the calc order lazy is right (each formula is already visited once; a sort saves nothing). C stays parked.

## Changes to the plan

1. Do B first, and make it wider. It is safer and probably worth more than the design says.
   - The loader already builds a formula cell's `input` from the parsed formula (`cell.input = Formula.text(expr)`, Xlsx.swift about line 425), for every one of the 182k formulas. So deriving it on demand gives the same text by construction: no save-fidelity risk for loaded cells.
   - Number cells do the same thing: `input = NumberFormat.full(n)` is formatted for every numeric cell at load. Make that lazy too.
   - Shape: `input` stored only when it cannot be derived (a typed cell whose text differs, an unparsable formula). Nil means "derive from the formula, else from the value". Keep the typed text for typed cells, or the formula bar changes.
   - `isFormula` reads `input.hasPrefix("=")` for unparsable formulas: keep that case working (those cells have `rawFormula`).

2. A as written would make things worse: `cached` cannot move to Extra. The loader sets `cached` on every formula cell that has a `<v>` (nearly all), so every formula cell would get an Extra object: 182k allocations plus a retain each. Keep `cached` in the hot part (or keep it only for the three cases value() uses it: unknown function, legacy array formula, external link; grep `.cached` for the save path first). Also keep `dynamic` hot (value() reads it on every evaluation; the design's list leaves it out).
   - So the cell will not be 40 bytes. Roughly: formula 8, value 17, cached 18, style, dynamic, extra 8: about 64. Measure it, do not estimate.

3. Extra must keep value semantics. Cell is a struct and is copied by undo, paste and restructure; a shared mutable class would let an edit of the copy change the original, and it would not be Sendable. Make it a final class with only `let` fields, replaced whole on write. Expose the moved fields as computed properties on Cell with their old names, so call sites do not change (this is not "touch every site").

4. Before A, split profile part 2 into copying vs hashing. A only helps copying. A formula's first read does about seven hashed operations (cells read, `_done`, `_visitingSet` contains/insert/remove, `_done` insert, cells write-back) and every later read does two (cells, `_done`). If hashing is the larger half, the cheap win is the done-check, without C: store a pass number in the cell (`donePass == engine.pass` means done), so a repeat read costs one lookup and nothing is cleared between passes. Keep `_visitingSet` for cycles as is.

## PR hygiene (act now)
#2168 is titled "docs only" but carries a code commit (320f8b60f, VLOOKUP result read through a new `cellValue`) with auto-merge on. Split it into its own PR with its own title. And in `cellValue`: for a cell with no formula it returns `cell.value`, but `value()` returns the spilled value when such a cell is empty (a styled empty cell under a spill). Simplest: `cellValue` just calls `value(sheet, a)`; add that case to the test.

## What to measure (each PR, before and after, same build mode, full pair env, fresh baseline from the same tree)
1. `MemoryLayout<Cell>.size` and `.stride` (print in a unit test).
2. `perf stat` user instructions and cycles, 3 runs each; not wall seconds (the box is loaded).
3. Time per phase: load (parse to workbook built), calc, print. B should show in load; A in calc.
4. Peak memory (`/usr/bin/time -v`, maximum resident set size).
5. Profile share of retain/release + Cell copy vs Hasher/dictionary find, to decide step 4 above and whether C is ever needed.
6. The other books (en-720207c0a4, ar-1cbfc66b64, ko-1443578502, en-667ad9b0a5) and one small book: none slower.

## Correctness checks the PDF text cannot give
The moved fields (input, rawFormula, arrayRef, keptAttrs) are read only by save and the formula bar, so identical PDF text proves nothing about them.
1. Save round trip: load, save, and compare every `<f>` and `<c>` attribute (vm/cm/ph, t="array" ref) in the sheet XML against the same round trip on the base binary. Must be identical on fr-ed293d08c8 and on a book with array formulas and unparsable formulas.
2. A unit test: copy a Cell, change an Extra field on the copy, the original is unchanged.
3. `~/bin/unit-tests.sh` (Sheets oracle tests) and the web build (`build/web-app.sh OfficeApp`).
