# amd-perf DESIGN (2026-11-23): faster sheet XML read (for planner review)

## Why
XML parse is 19% of fr-ed293d08c8, 25% of en-720207c0a4 (before the lookup fix), 33% of en-05e530c37b (perf, 20 pages). Self time is flat: String creation from bytes, Dictionary hashing, retain/release.

## What happens today
Xlsx._readSheet streams rows already (MiniXML `listUnder sheetData of row`: one row at a time, then dropped). So memory is fine. The cost is per CELL: the parser builds an XNode for `c`, one for `v`, one for `f`, each with a [String:String] attribute dictionary and a String name; then the reader looks attributes up by name (`c["r"]`, `c["t"]`, `c["s"]`) and parses the text again.

## Design
A byte-level cell scanner used only inside `<sheetData>` rows. For each `<c ...>`:
1. Read attributes `r`, `s`, `t`, `cm`, `vm` straight from the byte slice into small locals (no dictionary). `r` is parsed to row/col from the bytes (no String).
2. Read the children `<v>`, `<f ...>`, `<is>` from the byte slice. Numbers parse from the bytes (Double from UTF8 slice); text is built once, only when needed (shared-string index is an Int, so no String at all for `t="s"`).
3. FALLBACK: anything unusual (unknown attribute, `<is>` rich text, `<extLst>`, entity in a formula, namespace prefix, CDATA) makes the scanner give up on THAT cell and hand its byte range to the existing XNode path. So behaviour for odd files is the old code, byte for byte.
Row elements (`<row r= ht= hidden= ...>`) keep the old path: they are 1 per row, not per cell.

## Not doing
No change to Cell or Worksheet storage (that is dense row storage, separate, after this). No change to the writer. No new parser for other parts (styles, sst) in this step.

## Steps and checks
A. Scanner for cells with t in {absent, n, s, b, str, e} and `<v>` only (no formula). Measure instructions (perf stat) on en-05e530c37b, fr, en-720207c0a4.
B. Add `<f>` (plain, shared with si/ref, array with ref).
C. Stop if A+B gain under 8% of instructions on the three books: then report and park.
Checks each step: (1) 20-page PDF text identical on the three books plus 10 other xlsx2 books; (2) the SAVE ROUND-TRIP check: load, Xlsx.write, diff every xl/worksheets/sheet*.xml against the old build (RANDBETWEEN values aside), on 7 books incl. array, structured-ref, shared-formula cases; (3) a differential test: the scanner and the XNode path must give identical Cell values on every cell of ~60 corpus books (a unit test over the corpus cache, plus hand-written odd cells: entities, `<is>`, missing r, out-of-order r, cm/vm attributes); (4) 138 Sheets tests; (5) a fuzz pass: truncated and corrupted sheet XML must not crash and must fall back or fail as before.

## Risk
Medium: any attribute or child the scanner silently drops changes saved files. The fallback rule (give up on anything not explicitly handled) and the differential test are the guard.

## Expected gain
Half to two thirds of XML parse time: roughly 10-20% on en-05e530c37b, 8-12% on fr. Smaller than the lookup fix, so step C is a real stop point.
