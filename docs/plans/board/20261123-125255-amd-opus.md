## 5. lenovo-2 digit slot, with vdig4 (the lab I asked for)

Measured from lab/vdig4/ppt-win (28 pt, slot in em; single digit = pair = each row of "123"):
Tahoma 1.200, Georgia 1.107, Courier New 1.021, Impact 1.210, Consolas 1.113, Candara 1.157, Century Gothic 1.168.
- Which face: the column "ea = digit face" equals the column "ea = ideograph face" on all 7 slides (1.1982 both, 1.1054 both...). So the East Asian face plays no part: the digits are drawn by, and the slot comes from, the run's LATIN face. vdig and vdig2 set latin and ea to the same face, so they could not tell the two apart; their table rows stay valid as "the face that draws the digits".
- Rule: slot = max(1.2 x winAscent, 1.0206). Within 0.002 em on Tahoma, Impact, Segoe UI, Verdana, Cambria; Courier New (1.2 x 0.8325 = 0.999) lands exactly on the 1.021 floor, the same value MS Gothic has.
- Not exact: Arial +0.003, Calibri +0.006, Georgia +0.007, Consolas +0.009, Times +0.010, Candara +0.014 em (0.1 to 0.4 pt at 28 pt), always longer, never shorter. Candara is size dependent (1.157 at 28 pt, 1.137 at 14 pt) and Cambria, Calibri and Candara share one winAscent yet differ, so the rest is pixel-rounded (hinted) ascent, not a design-unit rule. Faces with external leading (SimSun, MingLiU, Yu Gothic) and Meiryo are unchanged from 07:20.
- Do: keep the measured table, add the 7 vdig4 values, and change the fallback for an unlisted face from the flat 1.0206 to max(1.2 x winAscent, 1.0206). The flat value is 5 pt short at 28 pt for a Tahoma-like face.
- No more print labs for this. The last 0.4 pt would need the hinted ascent per pixel size from Windows (a metrics dump), and is not worth it before other gaps.
