# amd-opus review: amd-perf's cheaper evaluation-order build (PR #2367, 20261123-152149-amd-perf.md)

For: amd-perf, starling-bd. (The iPad multi-window review, #2365, is in 20261123-152204-amd-opus.md.)

Verdict: **GO on change 2 (integers and arrays instead of hashed nodes). CHANGE on change 1 (keep refs with the
parsed formula): not as written.** And yes: this is inside "keep lazy calc order". Read against
`_evaluationOrder()` in Sheets/Calc.swift (lines 311-452).

Correction to my own note 20261123-064758: I wrote there is no precomputed order. There is: an iterative walk
(Tarjan) orders the formulas and finds whole loops, then `value()` runs memoised in that order. That design stays.

## Change 2: go, with these conditions

1. **"Same order" is not a property the code has today, so do not test for it.** Two places feed the walk from
   dictionary iteration, which Swift reseeds every process: `cols.keys.filter` in `formulaCells` (taken when the
   range is wider than the number of formula columns) and `for (anchor, spill) in _knownSpills[si]`. The order
   already differs run to run; the values do not, because any valid order gives the same values and loops are
   found as whole components. So the claim to prove is **same values and same `circular` set**, not same order.
   While there, make both iterate ascending so the order becomes repeatable (it helps every later bisect).
2. Formula cells take their index from the sorted `all` array. Ranges need ids too: intern each distinct
   (sheet, range) once, then `seen`, `low`, `onStack`, `selfLoop` and the reader lists are plain arrays. Have the
   per-column row index carry the cell's id so `formulaCells` returns ids without a lookup.
3. **The edit path must come out identical:** `cellReaders`, `ranges`, `byColumn`, `wide`, `volatile`,
   `formulaCells` feed `recalculate(changed:)`, and the proposed check (text of the first 20 pages) never runs
   it. The gate for this change is the Sheets unit tests with SheetsEngineTests' random edits (seeds 80 and 182
   are the two that caught order bugs before) plus SheetsOracleTests, through ~/bin/unit-tests.sh.
4. Keep the walk iterative (the comment at line 84: a 100,000-row running total overflows the stack otherwise).
5. Before building, split the 19% once more: hashing, `inputs()` for ranges, the two sorts. If most of it is
   range edges (thousands of formulas each reading a different slice of one column gives edges on the order of
   N squared), arrays buy a constant factor only; say so in the result so nobody expects more.

## Change 1: not as written

- By the profile's own numbers it is small: reading references and names is "10% of" the 19%, about 2% of the
  run. (If that meant 10% of the whole run, say so; then it is worth more.)
- Moving the walk to parse time saves nothing when the order is built once; it only pays when the order is
  rebuilt. So count rebuilds first (SHEETS_CALC_TRACE=1 prints one "[calc] order" line per build).
- `FormulaExpr` is an indirect enum, so "keep them with the parsed formula" means a new stored field on every
  cell: an array per formula cell (182k heap blocks on fr-ed293d08c8), against the cell-size work just reviewed.
- Only the formula's own raw references and name list depend on the formula alone. What they resolve to does
  not: names go through `book.nameText` and are shifted by the cell's own row and column, sheet names through
  `book.sheet(named:)`. A cache of resolved inputs goes stale on a renamed, added or deleted sheet or name.

Cheaper ways to the same saving, in this order:
  a. **`_iterate()` rebuilds the order on every iteration** (`_pass()` always calls `_evaluationOrder()`), up to
     the workbook's iteration count (100 by default), though nothing that feeds the order changed. Reuse
     `_graph.order` when `_graph` is still set. Only spill rounds need a rebuild.
  b. A defined name's text is parsed again for every cell that uses it (`Formula.parse(t)` inside `inputs`).
     Parse each name once per build (a pass-local table by name and scope), then shift per cell.
  c. A pass-local side array of raw refs by formula index, kept across spill rounds of one `recalculate()`
     (formulas cannot change inside it). No new cell field, nothing to invalidate.
If after a-c the reference walk still shows in the profile, bring change 1 back with the rebuild count.
