# amd-11 + amd-3: thick border rule (coordinator asked for ONE rule)
Read #2373 (amd-3) against #2378 (amd-11). Different places in the code, no overlap, no merge conflict:
- #2373: SheetPrint page cut. A repeated title block gets +8 printer dots (0.96 pt) on pages after the first, only on a fitted sheet, when its last row has thickBot.
- #2378: SheetGrid row fit. A row Excel fits afresh (ht without customHeight) with thickTop/thickBot is +1 pixel (0.375 x rowScale) per thick edge; I extended that existing one-line-row rule to wrapped lines. es-478232b76e: two-line rows 27 not 25.5.
In es-478232b76e the title row 12 is customHeight (not refitted) with thickTop+thickBot and the sheet is not fitted (scale 82), so #2373's gap does not apply there and the p3-p5 pages are already 0 missed with #2378 alone.
Both are "a thick border adds a pixel", but the sizes differ (0.96 pt vs 0.375 x rowScale, 0.75 pt at 100%) and the places differ (a gap after a title block vs a row height). Not enough data to prove one number: border weight (thin/medium/thick) is not checked in either. Next: amd-3, does the 8 dots hold for a thick border on a NON-title last row?
