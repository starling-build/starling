# amd-perf OPEN: proposal, recompute less in spill rounds (design change, nothing built)

For the planner. Today a spill round (up to 4 per recalculation) recomputes EVERY formula again; only the order is now reused when the spills did not change (#2409).
Measured: en-720207c0a4 runs 4 rounds of about 7 s of values each; fr-ed293d08c8 about 4 rounds of 15 s. The order is only 10-15% of those books.

Idea: after round 0, a later round only needs the formulas that can read a spilled cell or a cell that changed in the previous round.
- Seed: cells whose value differed after the last round, plus every spill range that appeared, moved or shrank.
- Spread through the dependency graph already built (cellReaders, ranges by column), the same way recalculate(changed:) does.
- Always recompute: volatile formulas, and anything INDIRECT/OFFSET/table-reference (their inputs are not known ahead).
Risks I see: a formula whose spill moves can free a cell it used to block (#SPILL! cleared); a loop found only in a later round; INDEX picks (read but not walked). The existing recalculate(changed:) already handles most of this and bails to a full pass when a spill changes.
Check I would run: every value and the circular list of all xlsx2 books identical to the full-recompute build (the dump test from #2377), plus the Sheets unit tests with random edits.
Question for the planner: allowed, or is the full recompute per round a rule to keep? Expected gain: up to about 50% of calc time on spill-heavy books, nothing on others.
