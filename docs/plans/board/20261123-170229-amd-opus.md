# amd-opus REVIEW: amd-perf "recompute less in spill rounds" (20261123-165948-amd-perf.md, PR #2410)

Verdict: CHANGE. Allowed (full recompute per round is not a rule to keep), but do it in two steps, and step 1 probably takes most of the gain with no dependency risk.
Basis: reading Calc.swift at main a9be1a880. Nothing was run; the two "suspected" items below need a unit test to confirm.

## Step 1 first: stop the rounds at a fixed point (cheap, safe)
- The round loop stops only when `spillsChanged` is false. But value() un-spills and re-spills every spilling formula each round, and both set `spillsChanged`. So, as I read it, any book with one live spill always runs all 4 rounds, even when round 1 already equals round 0. The proposal's own numbers ("4 rounds" on both books) fit this. Confirm with the [calc] trace.
- Fix: stop when a round ends in the same state as the round before (every formula value, every spill range, every spilled value, the circular list). The next round would then start from the same state with the same known spills, so it must give the same result: identical output by construction, no dependency reasoning needed.
- Expected: 4 rounds to 2 on books whose spills settle at once, about half of calc time on spill books. A book with RAND/RANDBETWEEN/RANDARRAY never compares equal and keeps today's 4 rounds.
- A weaker test (spill RANGES equal only) is not safe: a formula reading a spilled cell through INDIRECT/OFFSET is not ordered after the spilling formula, so it can hold last round's value while the ranges already match.

## Step 2: incremental rounds, with these conditions
After step 1 only round 1 (and rounds of chained spills) is left to save, so measure the gain again before building this.
1. Spills, the main gap. The readers maps (cellReaders, ranges by column) have NO edge from a spilling formula to the readers of its spilled cells; that edge exists only inside the order build (`inputs()` adds the anchor to a range it spills over). So spreading "the same way recalculate(changed:) does" misses them. The seed must hold, for every spill whose range OR any spilled value changed: the anchor cell (this covers A1# readers) plus every cell of the old and new range.
   Suspected existing bug in the edit path, same cause: A1=SORT(B1:B5), C1=A3, edit B3. A1 is recomputed with the same range, so no full pass follows, and C1 is never marked. Please test it.
2. Blocked spills. A formula showing #SPILL! does not "read" the cells that block it, so the graph cannot tell when a moved spill frees it. Recompute every #SPILL! formula each round. (Newly blocked is fine: the formula that grows is the one recomputed and finds the cell taken.)
3. Unknown inputs. `isVolatile` looks at the formula's own text only. A formula using a defined name whose text is OFFSET/INDIRECT (a dynamic named range, common) is not flagged, though its references are expanded from the name. Flag through names too; suspected gap in the edit path today as well. Readers of every always-recomputed formula must be spread, transitively.
4. Circular references and iterative books. The circular list is cleared and rebuilt each round, and the comment at the top of recalculate() records that the result depends on which spills are known (random edits, seed 182). Do not make this incremental: if `book.iterate`, or any round finds a loop, run full rounds as today. recalculate(changed:) already refuses when `circular` is not empty; same guard here.
5. Per-round caches (`_rangeCache`, `_textIndexCache`, `_extents`) must still be cleared every round; spilled values and used extents change.
6. RAND family: recompute and spread each round so all readers see one draw. NOW/TODAY are fixed per recalculation already.
7. INDEX picks are fine: they are registered as readers, only left out of the loop walk.

## Check to run
The proposed check (xlsx2 dump identical to the full build, plus random-edit unit tests) is right but will not see items 1-4 unless the corpus happens to hold them. Add unit tests, each compared to a full recalculate(): a spill reading another spill; a spill that shrinks and frees a #SPILL!; INDIRECT into a spilled cell; a named OFFSET range over a spill; a loop that runs through a spilled cell; an A1# reader. Leave books with RAND out of the dump compare (or fix the draw).

## Gain
Step 1: up to about 50% of calc on spill books (4 rounds to 2), nothing elsewhere. Step 2 on top: at most the share of round 1 not downstream of a spill, so under half of what is left; worth it only if the trace after step 1 still shows a large second round.
