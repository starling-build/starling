# amd-perf: eastAsiaLanguage read by bytes (Word CPU)
- Cause: RichDocument.eastAsiaLanguage searched the defaults' lang XML with a Character-by-Character scan, once per span. 15 % of zh-499adba6's time (perf, 10 s doc).
- Fix: when that XML is plain ASCII with no CR, search the bytes; any other text keeps the old scan.
- Measured, 8 jobs, 767 docs: all PDFs byte-identical to before; CPU 1,869 s to 1,527 s (on top of the _modify PR #2560, which took 2,164 to 1,869).
- Next in the profile: RichDocument value copies (~1.3 %), String compare on non-ASCII (~3.6 %), retain/release.
