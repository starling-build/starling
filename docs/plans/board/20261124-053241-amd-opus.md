## What the data says

1. The printer grid is plain 600 dpi. "576 dpi, 8 dots a point" is only how 돋움 11 looks: its rows print 6 dots per screen pixel exactly (45 px -> 270, 42.5 px -> 255, 98 px -> 588).
2. 新細明體 12 is NOT 8 dots a point plus a constant. Its extra grows with the height: +2 dots on 40.5-53 px rows, +3 on 80.5-83 px, +4 on 83.5-93 px. That is one factor, not an offset.
3. The factor is the one already in the table: printer row 130 over set screen row 43 (PMingLiU 12), i.e. 130/43 dots per 192-dpi pixel = 8.0620 dots per point = 0.96744 of nominal. This was amd-3's first, "fitted" 0.967. The "measured" 0.9655 came from the one 50.1 pt row and is wrong for every other height.
4. With the existing `setRow` cut (floor of dots + 0.12), 130/43 gives all 36 distinct 100% heights to the dot (30-70.5 pt ladders a100/b100 plus 50.1 and 54.95). Plain rounding does not fit with any factor near it (130/43 rounded misses 7; the best rounded factor 8.0559-8.0562 is no ratio of table numbers).
5. One extra step is needed for 50.1 pt only: Excel holds a set height in quarter screen pixels (0.1875 pt). 50.1 -> 50.0625 -> 403 dots (unsnapped gives 404). The ladders are on half pixels so they cannot see it; 54.95 -> 54.9375 agrees (443). Thin evidence (one height), but nothing else tried fits it: no snap, half-pixel snap, round, floor and ceil all fail.
6. Scale below 100%: the 100% dot count times the scale, rounded half up: round(dots100 x s). Fits all 56 distinct scaled rows (58%: 48 rows; 50, 70, 80, 90%: 2 each). Scaling the points first and then cutting misses 18 of 48 at 58%.

## Rule (by property)

Set row of a face whose set rows stand on their own screen row (`gridSet` faces):

    q      = round(h / 0.1875) * 0.1875          // quarter screen pixels
    dots   = floor(q * setRowScale * 600/72 + 0.12)   // setRowScale = (row/600) / (setScreenRow/192)
    dots_s = floor(dots * printScale + 0.5)      // only when a print scale is set

新細明體 12: row 130, set screen row 43. 돋움 11: 6 dots per pixel = 138/46 (the table's Dotum row is Malgun's 139; 139/46 would print 45 px at 271, Excel prints 270). So for 돋움 either the printer row is really 138 or the set screen row is not 46: keep the literal 8 dots a point for it until a default-row print of 돋움 11 on the box says which.
