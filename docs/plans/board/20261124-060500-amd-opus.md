# SPEC (amd-opus) for amd-1: Word autofit table with cell spacing (lab tbauto, dx2 1dd7c7a3fae8)

Answer to the puzzle in /data/landq/opus-puzzles.log (amd-1, 2026-11-24). No new lab needed: one model fits all eight prints
(/data/s/amd-1/starling/lab/tbauto/word-win) to 0.12 pt.

## What Word does (s = tblCellSpacing, n = columns, m = cell side margins)

1. GEOMETRY, every layout. Each cell is a BOX (text + its margins). There is 2s before the first box, 2s between boxes,
   2s after the last. The table's left outer edge stays where the unspaced table's is (text of column 1 at edge + 2s + m).
   On the 600 dpi print s = 50 twips is 21 dots = 2.52 pt, not 2.50 (text x 81.02 = 72 + 5.04 + 4).
2. A stated cell width (tcW / grid) is the BOX width; spacing is added on top, never taken out of it.
   Fixed layout (t8): box 1 = 150.01 for tcW 3000, column 2 text at 236.09 = 72 + 5.04 + 150 + 5.04 + 4.
   Table outer width = sum of boxes + (n+1) x 2s (465 here, past the margin; fixed tables are not held to the room).
3. AUTOFIT, tblW auto (t1 to t5): the same narrowest/widest sharing as the unspaced table (the contentFit branch of _autofit),
   run on the boxes, with
     room for the boxes = unspaced room - 2 n s      (so the outer table is the unspaced room + 2s wide)
   Narrowest and widest of a box are unchanged by the spacing (content + margins; widest at least the first row's tcW;
   widest capped at 1580 + margins). Unspaced room here = text width 451.28 + 4 (table edge on the margin, lab t6).
4. AUTOFIT, tblW dxa (t7): the stated width is the OUTER width, all spacing included:
     room for the boxes = tblW - (n+1) x 2s
   and the same sharing runs (the grid is not kept; ours kept it: 228.5 against Word 170.3).

## In our code's terms

Our column slot holds the spacing: first = 2s + box + s, middle = s + box + s, last = s + box + 2s (the padding at
RichLayout+Paragraph+Funcs.swift ~397), so slots sum to boxes + (n+1) x 2s.
- Fixed / held widths: slot = stated width + 2s, + s more for the first and for the last column. Today slot = stated width,
  which is why t8 reads 228.5 against 236.1 (3s short) and every box is 2s to 3s too narrow.
- Autofit: let _autofit run when cellSpacing > 0 (line ~1320), on BOX widths: base = grid, room reduced as in 3 or 4,
  then add the spacing to each result as above. The cell insets it uses must NOT include the spacing.
- Round the spacing to print dots only if a 0.04 pt per gap matters (it does not for line breaks).

## Not proven, say so in the commit

- n > 2: "2 n s" and "(n+1) x 2s - 2s" are the same number; with two columns the labs cannot tell any other form apart.
  A three-column lab would (one round, optional; the box-and-gap geometry makes this the only natural reading).
- A stated tblW wider than the room, percent widths, and nested tables with spacing: not in the lab.

  That is our slot convention, not a second measurement: with the slots widened as above it still holds. Its files are
