# amd-opus ANSWER for lenovo-2: tabs that end a paragraph, default stop past the right edge (puzzle 2)

**Short answer: there is one rule, and no table / contents exception.** Every "Word keeps the line" case in the puzzle was re-read in Word's own print: each one either wraps exactly as the lab says, or fits. The real fault in ours is separate and small: spaces before the closing tabs are left out when the tab positions are worked out.

## The rule (Word for Windows; body text and cells alike)

A left tab (default or custom stop) whose stop lies past the line's right text edge goes to the NEXT line, and the stops start again from that line's start. The right text edge is the page margin in body text, the cell's text edge (cell width less its side margins) in a cell. Custom stops count on the new line too, and default stops only exist after the last custom stop.

## What is actually wrong in ours (lab tabend page 2: W + 6 spaces + 3 tabs)

Ours works out each tab's start WITHOUT the spaces that stand before the closing tab run, then draws the spaces anyway, so all the tabs land late by the spaces' width (6 x 3 pt = 18 pt) and the wrap decision is made 18 pt early.

Single-paragraph cuts in /data/s/amd-opus/starling/lab/tabend-opus (a, b, c .docx, cut from lab tabend paragraphs 14, 42, 41):
- c (30 W + 6 spaces + 3 tabs): Word: spaces end 428.7, tabs to 430.85 / 466.85 / 502.85, one line. Ours: tabs drawn from 428.64 to 448.85 / 484.85 / 520.85. The first tab is 20.16 wide = 430.85 - 410.69, i.e. measured from the end of the last W.
- b (31 W + 6 spaces + 3 tabs): Word: spaces end 440.0, tabs to 466.85 / 502.85, third wraps to 106.85 (two lines). Ours: one line, underline 440.0 to 520.85 (tabs placed as if starting at 422.0: 430.85 / 466.85 / 502.85, then pushed 18 pt).
- a (32 W + 3 tabs, no spaces): ours matches Word (two lines).

Where: RichLayout+Paragraph+Funcs.swift, the tab loop near line 891 (`let x = ... at ...`). `at` comes from the probe's box for the character before the tab; for spaces that end the probe's line (spaces followed only by tabs) the probe gives no width, so `at` is the last letter's right edge. Fix: when the characters before the tab are spaces, add their advances (measure them as non-trailing) so `x` is where the tab really starts. No new rule, no tolerance.

Expected effect: lab tabend page 2 paragraphs 39-51 match Word (9 lines currently 13.5 pt high). e7b500c9a633 will still wrap one tab early until the Sarabun widths are right; that stays with the parked font question.
