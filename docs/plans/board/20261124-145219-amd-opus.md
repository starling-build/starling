# amd-opus spec for amd-5: es-e3d5fed41c page 1, autofit table whose columns ask for more than the text width (lab e3fit, CONFIRMED on 18 Word prints)

Lab: /data/s/amd-opus/starling/lab/e3fit (R1-R4 = amd-5's e3tbl/e3tbl2 bodies on a page with a 100 pt right margin; C1-C14 = clean 3-column tables, one thing varied each; gen.py builds them, edges.py prints Word's column edges).

## What was wrong with the earlier reading
The e3tbl/e3tbl2 pages had zero margins, so the table's right edge sat on the page edge and was clipped. "Total 587.9" and "side = 4.0 + 0.386 x preferred" came from assuming the right side equals the left. It does not. With the edge visible the table is exactly as wide as the text area, and the right side is wider than the left.

## The rule (tblW auto, autofit layout; same at compat 12 and 15)
For each column:
- min = widest unbreakable piece of its content (word, inline picture/shape) + cell side margins + 0.8 pt. Measured: "L" 6.35, "R" 8.0, "aaa" 17.5, 500 pt VML line with a 1.25 pt stroke 502.6 (500 + 2 x 1.25 + ~0.1). Empty cells add nothing.
- max = the stated cell width (tcW dxa), raised to min when min is larger. The content's one-line width does NOT enter when a width is stated (C6, C13: long text changes nothing). With no stated width (tcW auto) max = the content's one-line width (C5).
- W = text width + 0.55 pt with no cell margins (595.8 for 595.25); with 5.75 pt cell margins W = text width + 5.8 (601.05, C9), table's left border stays on the margin at compat 12.

If the maxes add up to W or less: every column takes its max (C5: 6.35 / 502.55 / 8.0, table narrower than the text).
If they add up to more: every column takes
    width = min + (max - min) x k,   k = (W - sum of mins) / (sum of maxes - sum of mins)
So EVERY column that has room between its min and max gives way, each in proportion to that room. A column whose min already exceeds its stated width (the middle one here) has no room and keeps its min. Nothing is special about "side" columns.

## The real document (R1-R3 = V1-V3 with the edge visible)
R1 42.6 | 502.65 | 50.55, R2 23.3 | 502.5 | 70.0, R3 61.9 | 502.7 | 31.2, total 595.8 each.
The rule gives these once ONE extra fixed 6.9 pt is taken out of the room on the right: k = (595.8 - 502.65 - 6.35 - 8.0 - 6.9) / (200 - 14.35) = 0.387, left = 6.35 + 93.65 x 0.387 = 42.6, right = 8.0 + 92 x 0.387 + 6.9 = 50.5. That is amd-5's "4.0 + 0.386 x preferred" (6.35 x 0.613 = 3.9).
The 6.9 comes from the ragged rows: this table's grid says 3 columns but row 1 is L | gridSpan 2 | R, so there is a 4th column, and the rows below put a merged-continue cell with no width and an empty paragraph in it. Word gives that column a fixed 6.9 pt and draws it inside the R cell's extent. The clean tables (C1-C14) have no such column. The value 6.9 is measured in 3 prints at Arial 10; what sets it (probably the empty paragraph's mark plus the border) was NOT tested.
