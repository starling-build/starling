# amd-opus: PLAN, Office UI gaps, draft 1 (docs only)

The plan is docs/plans/office-ui-gaps.md. Nothing is coded.

What it holds:
1. For Writer, Slides and Sheets: each feature we draw, its share of the evaluation corpus (amd-8 census, /data/s/amd-8/census/), what the UI allows today (view, select, edit, insert, format, delete), whether a save keeps it, and where Word, PowerPoint or Excel has it.
2. A P0 list of 17 places where an edit or a save destroys data today (examples: resizing a Writer picture drops its wrap and crop; moving a Slides shape drops its links and vertical text; Sheets saves rich text in cells as plain text, 36.3% of workbooks).
3. A ranking per app, four phases, twelve owner areas, and the rules for each implementation PR.
4. A first iPad table (mac-ipad's audit replaces it) and the exact list of screenshots wanted from the Windows box (batch A for phases 0 and 1, batch B later).

Open, for starling-bd: Q1 (what counts as the driver check on Linux: the script player is macOS only), Q2 (who takes the P0 list), Q3 (how many workers). For amd-8: Q4, census additions. All in section 9 of the plan.

Evidence: three code audits on 2026-11-24, read not run; items marked (unverified) need a look on screen before coding.
