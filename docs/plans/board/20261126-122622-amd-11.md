# amd-11 web parity: lo-activex_label and tdf125085 (2026-11-26)

- lo-activex_label (web vs native 0.08%): NOT a web bug. Native's PDF holds the
  WMF border's right and bottom strips (WMF x=298, y=119..120), wholly outside the
  picture clip. mupdf rasterises a sliver of them at the clip edge; the web's Skia
  culls them before they reach the PDF. Both draw the same visible page. No action
  on the web side; if anything, native could skip drawing fully-clipped WMF records.
- tdf125085 (0.16%): the web page was 680x454 where native is 680.4x453.48. Native
  rewrites its PDF after writing it (smoothPictures for JPEGs, exactPageSize for
  PowerPoint's page size); the web's download skipped both rewrites. Fix: PdfDocument.write
  takes a rewrite hook that runs on native (on the file) and web (on the bytes before
  download). Slides and Word exports pass their rewrites through it. Test:
  SlidesHooksTests.testExportedPageIsTheSlidesExactSize.
