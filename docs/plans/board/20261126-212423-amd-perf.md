# HANDOFF amd-perf: screen readers in the browser build, first cut (Word checked)

What landed in this PR (plan: docs/plans/web-parity.md section 5):
- sdk/Sources/FlutterWeb/WebAccessibility.swift: reads the same semantics snapshot the AT-SPI and VoiceOver bridges
  read and sends it to the page as JSON (at most every 250 ms after a frame, only when it changed). ScreenReader
  announcements go to the page. Off until the page turns it on.
- web/host/a11y.js (new, installed by web-app.sh, office-landing.sh, office-product.py): one ARIA element per node
  in a transparent layer over the canvas; aria-activedescendant names the focused node; a reader's click runs the
  node's tap; two aria-live regions. Turned on by a visually hidden "Turn on screen reader support" button (first
  in the Tab order), ?a11y=1, or the remembered choice (localStorage starling-a11y).
- Office toggles (Bold, Italic, view switches, Spelling) now report "off" as well as "on" (they used to drop the
  toggle state when off, so a reader heard a plain button). Native readers get this too.
- Tests: SemanticsWidgetTests.testAnOffToggleIsStillAToggleAndAPlainButtonIsNot (fails before),
  test/web/a11y-test.mjs (roles, in test/run.sh).

Checked in Chrome (web-drive, ?a11y=1, textedit.docx): ribbon buttons with names, Bold/Italic as switches with
their state, Undo disabled, document as a textbox named "Document" holding the text and focused; clicking the
Italic element through the layer turned Italic on and "Italic on" reached the polite live region.

Left (next steps, in order):
1. Ribbon tabs (File, Home...) come out as plain text, not tabs: the tab strip gives no button/tap semantics.
   Same gap natively. Fix in the Office chrome (role tab + selected).
2. Keyboard shortcuts (Ctrl+B) change the state but announce nothing; only a click on the button announces.
3. No real NVDA/VoiceOver pass yet: needs a Windows or Mac browser. The page side follows ARIA 1.2 only.
4. "Find in document" box appears twice (text field plus its label); the native bridges show the same.
5. Slides and Sheets: same layer works (it is app-independent) but not yet driven.

Trap: snap Chromium reads files only under $HOME; test/office-layout.sh keeps its work in TMPDIR (/tmp), so its
browser half fails "NotFoundError" unless TMPDIR is under home. Under load (>250) it also flakes with
"document did not open" on a different doc each run; a quiet rerun passed everything.
