Two commits, tests SheetsPrintTests.testDotumAndGulimRowsAreTheirOwn and testDotumGulimBatangCentreOnTheirWindowsAscentDescent.

## What

1. Rows. SheetPrintMetrics gave dotum and gulim Malgun's rows (139 dots at 11 pt, screen 45). Excel prints them in their own faces (the corpus prints embed Dotum and Gulim) with their own rows:
   - print row = em dots at 600 dpi + ~10: 77 85 93 98 102 110 127 143 160 (8..18 pt; lab cjkrows3, amd-1).
   - screen row = em in whole px at 192 dpi + 5: 26 29 32 33 34 37 42 48 53. This fits 11 pt (24 pt set rows print 23.05) and 10 pt (ko-3ca2381bbc's 굴림 10 set rows at 0.93).
   - amd-1's earlier try dropped 7 books because it changed the print row but kept Malgun's screen row, so every set row shrank about 27 %.
   - Lab xls-rowkeep (starling-bd 2026-11-26): Excel ignores unmarked .xls row heights (no 0x40). 돋움 11 rows print 12.24 pt, so there is NO "keep stored .xls heights" rule.
2. Centring. With the shorter rows, the painter's fallback centring put centred Dotum and Gulim text about 2 pt low. The font files on the print box have win ascent 879 and descent 145 of 1024 (Dotum, Gulim and Batang alike), so the ascent table now holds 0.8584/0.1416 for them.
   - ko-7fdeb278e7 32.4 -> 94.8 and ko-455774eb65 32.8 -> 77.3 (rows only -> rows + ascent).
   - The old test said Dotum and Gulim must keep the painter's ascent, citing ko-946b4369d3 and a 0.90/0.21 pair. That pair was wrong; with the real 879/145 ko-946b4369d3 goes 97.8 -> 99.5.
