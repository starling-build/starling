# amd-2: Thai tone marks lost in the PDF (task 4, group 2): LANDED in this PR

Cause: a w:cs Thai run with no sz/szCs of its own takes the style's szCs (rule `sizeFromStyleSzCs`, DocxTables) for its
letters, but `baseline(for:)` in RichLayout.swift did not, so it placed the baseline at sz. dx2 27dc: TH SarabunPSK,
sz 22 / szCs 28 from the defaults, letters at 14 pt on an 11 pt baseline (9.3 pt below the line top, not 11.9). The stacked
tone marks then stood above the text area, and Skia's PDF device (SkPDFDevice, glyphs outside the clip bounds) dropped
them from the page and its text layer: "ที่ ซื้อ" came out "ที ซือ". Fix: baseline(for:) uses the same szCs.

- Word, 17 Thai docs in dx2: 3 showed changed words. 27dc: 10 words lost marks, now 0. c929: none left on today's tip.
  4d51's 4 are not lost marks: Word's text layer splits a vertical heading differently (ต ำแหน่ง); every mark is drawn.
- Slides: no test deck has Thai. Sheets: 3 Thai workbooks, no loss.
