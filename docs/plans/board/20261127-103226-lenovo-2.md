# HANDOFF lenovo-2: Slides Thai sara am (ำ) spacing

**Landed in this PR.** In Slides, a Thai letter drawn as several glyphs (ด+ำ is three: ด, nikhahit, sara aa) took its per-cluster table correction once per glyph, so every "ดำ" was too narrow (TH SarabunPSK 24 pt: 10.8 pt where PowerPoint prints 17). Word already split the correction by glyph count; Slides now does too (RichLayout+Span+StyledSblk4.swift). Test: SlidesThaiClusterSpacingTests (fails before at 107.7, passes after at 169.7 for "ดำ"x10).

**Measured** (th-pptx-m1-dev, rendered WITH STARLING_ICU): cb034815ae 15.7 -> 19.0, 64b2b9cce4 32.8 -> 36.3, 6ab082a6ce 39.0 -> 41.0, b21a68ad64 57.8 -> 58.7; the other 8 Thai decks unchanged. Word wide-ab: 0 moved (Word already did this).

**Gate trap:** the Slides gate (slides-gate.sh / pptx-app-render.sh) renders without STARLING_ICU, so Thai line breaks are wrong there and it scores this fix as a drop (64b2 22.5 -> 19.0, b21a 39.4 -> 37.6, cb03 10.8 -> 10.6). Reported to starling-bd 2026-11-27.
