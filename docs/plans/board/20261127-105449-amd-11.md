# HANDOFF amd-11: web parity 4, Save As and Save in the browser (Word)

Landed in this PR:
- Chrome/Edge: Save As asks the browser's save picker for a place (Word's formats, the document's own
  first) and keeps the file's handle; Save writes back to it. A file opened through the open picker
  saves back to itself. A refused write leaves the document unsaved.
- Firefox/Safari (no pickers): Save downloads; Save As is a name-and-format box (Backstage Save As,
  names only), then a download.
- Ctrl+Shift+S goes through the same Save As as the menu (natively unchanged).
- web-drive hides the real pickers unless PICKERS=1 (their dialogs cannot be answered by a script);
  PRELOAD=file.js runs before the page's scripts.

Tests: BrowserSaveAsTests (6, native, stand-in pickers); test/office-saveas-web.sh (Chromium,
stand-in pickers over the origin private file system): 7/7. test/office-recovery-web.sh still 6/6.

Left: Slides and Sheets still download on Save; Recent (PR #3204) should keep the handles so a
recent file reopens writable; Print for Slides and Sheets; a recovery flush on page close.
