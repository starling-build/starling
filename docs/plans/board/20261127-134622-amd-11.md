# HANDOFF amd-11: web recovery flush on page close (web-parity item 2)

- What: a browser tab that is hidden or closed writes Word's recovery copy at once.
  Before, only the 2-second AutoSave timer wrote it, so typing and closing the tab
  inside 2 s lost the edit.
- How: page `visibilitychange`/`pagehide` -> wasm export `starling_page_hidden` ->
  `hostPageHidden` -> `OfficeScene.flushAll()`. Word skips the write when the copy
  already holds the current revision (tab switches do not rewrite it).
- Tests: BrowserRecoveryTests.testHidingThePageCopiesAtOnceAndOnlyOnce (fails before:
  rewrites on every hide); test/office-recovery-web.sh step 4 (fails on the old build).
- Left: Slides and Sheets have no browser recovery copy yet (their shells register
  flushers, so they get the hide flush once they keep a copy). A real tab close in
  Chrome is best effort: IndexedDB writes started in pagehide usually finish, not always;
  visibilitychange (fired first on close and on mobile app switch) is the reliable one.
