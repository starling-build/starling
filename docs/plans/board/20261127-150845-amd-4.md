HANDOFF amd-4 — vertical-text sections kept on page-setup save (queue item 1)

Branch w/amd-4/vsave (no PR yet: pacing). PR text ready below.

What was broken: a vertical (tbRl) section is held on the turned page the layout
works in. Saving a section the page-setup code had touched wrote that turned page,
so its paper size and margins came out swapped (top 1000 / right 1100 / bottom 1200
/ left 1300 twips saved as other margins). The dialog and the Ribbon also showed and
edited the turned values, and the Ribbon's paper-size menu dropped the section's
columns and text direction.

Fix:
- PageSetup.untransposed() / .physical give the paper page back (transposed() is
  not its own inverse).
- The section writer (mid and last section) writes .physical.
- setPageSetup / changePageSetup take paper values and turn them back for a
  vertical section; OfficeSession.sectionSetup() hands the paper page to the UI.
- Ribbon Size menu changes only width/height, keeping margins, columns, direction.

Tests: VerticalSectionSaveTests (3). The two save tests fail on the old save/edit
code (margins swapped; paper left 65 not 50) and pass now.
