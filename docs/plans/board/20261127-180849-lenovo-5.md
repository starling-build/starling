# lenovo-5: W-OB-3 Arrange, z-order across paragraphs (DESIGN)
2026-11-27. Picture Format > Arrange: Bring Forward, Send Backward, Bring to Front, Send to Back.

Today: a floating object is painted inside its own paragraph's paint (RichLayout+Paint `_paintParagraph`, the
`_floatPaintOrder(i)` loop). relativeHeight only orders the objects of ONE paragraph, only under wordWindowsPages.
So paragraph 5's object always covers paragraph 2's, and paragraph 5's text paints over paragraph 2's in-front object.
Behind-text objects are painted per paragraph in the shading pass (`_paintShading` with `_shadingFloats`), in paragraph order.
Headers and footers paint before the body flow, so they are already under it.

Word's stacking (to confirm with one lab):
1. header/footer story under the main story, as a whole;
2. in a story: behind-text objects (behindDoc=1), then text with inline pictures and tables, then every other floating
   object (square, tight, through, top-and-bottom, in front), each layer ordered by relativeHeight, ties by document order.

Paint change:
- Body flow pass: a floating object that does not take room (the `!takesRoom` branch) and is not behind text is not
  drawn in its paragraph; it is recorded (paragraph, item k, the piece's translate and clip) instead.
- After the flow's text pass, the recorded objects are drawn sorted by (page, relativeHeight, paragraph, k),
  each under its piece's translate/clip again.
- Behind-text pass: the same sort over the page's behind objects before the text.
- Header/footer paint: the same two-layer sort inside the header story.
- Objects with no relativeHeight sort as 0 in document order (today's behaviour for a lone one).
- Applies with theme.wordRules (editor and fidelity alike), not only wordWindowsPages, so the editor shows the order.
- Top-and-bottom (takesRoom) objects join the front layer too (advisor): they sit above text like square ones.
- VML z-index is read as well (negative = behind text, value orders the layer).
- One ordered stack per page: paint it forward, hit-test it in reverse (today `_inlineImage` searches forward,
  `_floatingImage` in reverse).
- The paragraph's own picture path and vertical-cell floats get the same deferral.
- Skip decisions (piece continues, drop-cap pass 1, already drawn behind, vertical page picture) are made when
  recording, not at the flush. The flush runs once, after drop-cap pass 2.
- PDF text order changes: check the scorer does not depend on it.

Advisor-checked 2026-11-27.

Commands (controller, one undo step, round trip): among the floating objects of the same story and same layer
(behindDoc equal), the object moves one place up or down the layer's stack (new height midway between its new neighbours);
to Front = document-wide max + 1024; to Back = below the lowest (renumber the layer if no room). LANDED in this commit. Bring in Front of /
Send Behind Text are the existing wrap choices.
