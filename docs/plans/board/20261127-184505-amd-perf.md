# amd-perf: screen-reader unit test flake fixed (AtspiBridgeTests)

What broke: testScreenReaderClientSeesNamedButtonAndPressesIt failed under load (b127, b129) and passed alone.
Cause: at-spi-bus-launcher puts the accessibility bus socket in $XDG_RUNTIME_DIR/at-spi. Every copy of the test on
the box (parallel shards, other sessions, same Unix user) shared /run/user/1000, so one run ending removed or replaced
the socket another run's python client was about to use; the client aborted with
"dbind-ERROR: AT-SPI: Couldn't connect to accessibility bus" (SIGABRT, no stdout), seen once stderr was captured.

Fix: the test makes its own runtime folder (mkdtemp), sets XDG_RUNTIME_DIR for the run, waits for the bus and launcher
to exit, then removes it. Client stderr now goes into the failure message.

Measured: the test binary run 8 at a time, 12 rounds each: 21 of 96 failed before, 96 of 96 pass after, no folders left.
Nothing left open.
