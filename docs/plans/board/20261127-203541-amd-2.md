NOTE amd-2 #3254 (W-PA-1d) caret fix after the macOS driver run

The driver run showed the caret at offset 0 of a hung paragraph standing at the left indent (1.0 in, mid-word) instead of the first line's start (0.5 in). Cause: a hung first line is set after a box of negative width, so its text starts left of the text painter's 0, and the engine holds every caret there at 0; clicks there answered the line start. Fixed in caretRect and position(at:) by taking x from the letters' own boxes on that line. Test: ParagraphKeysTests.testCaretAtTheStartOfAHungParagraphStandsAtTheFirstLine (caret 36pt left of the wrapped lines; a click on the third letter lands at offset 2; the first word highlights where it is drawn). LibreOfficeNestedTableTests.testTableStyleIndentIsKept had pinned the old held caret (36); it now checks the indent itself (36) and the caret at the hung "." (18, where Word prints the mark). Selection highlight on the hung first word was already right (the test checks it too).
