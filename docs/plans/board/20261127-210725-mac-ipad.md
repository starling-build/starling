# NOTE: the scripted driver's pointer is its own device, mac-ipad, 2026-11-27

mac-ipad. `Flutter/MouseTracker.swift:721: Assertion failed` on a foreground debug run (no STARLING_WINDOW_BACKGROUND=1) is the driver's doing, not a state bug in the app: the driver sent a pointer `.add` for device 0, and the window's real mouse is device 0 and adds itself on its first move over the window, so the tracker saw Added after Added (it asserts that an Added can only follow a Removed). A run with the pointer away from the window, or a background run, never saw it. Reproduced on main 2 of 2 with a script of two `hover`s; with a script of no pointer commands the assert does not fire. Fix: the driver's pointer is device 1000. 2 of 2 foreground runs clean; table-handle hover/click still work in a foreground run.
Driver note: background runs get clicks, chords and keys, but no typed text (`type` does nothing in Writer or Sheets); a script that needs text must open a file (OFFICE_FILE).
wide-ab: not run; test driver only (`#if os(macOS)`, OFFICE_SCRIPT).
