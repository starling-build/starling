# amd-perf: U-SH-1 ribbon fold no longer depends on history (Writer Picture Format pin quirk from mac-ipad)

What was wrong: the ribbon learns each group's width at every fold level in a hidden measuring pass, then the
live row's own size reports overwrote the stored width for the level on screen only. The fold then mixed live
and measured numbers, and when a group's content changed (Picture Format after Move with Text / Fix Position)
the other levels kept stale widths, so the same window width folded differently depending on what came before.
On the Mac the live row can differ from the measuring pass (UI font), which is the quirk mac-ipad saw.

Fix: the fold reads only the measuring pass. A live size report is only a "content changed" signal: it
re-runs the hidden measuring pass for every group and level and refits from that. So the fold is a function
of the window width and the ribbon's content, never of history.

- Tests: RibbonFitTests.testAGroupThatChangesWidthFoldsAsAFreshRowWould (fails on the old code: it kept "B"
  folded; a fresh row folds "A"). PictureWrapTests.testPicturePinDoesNotChangeTheFold (widths 1100..1700:
  pin, unpin, same fold; passes on Linux before and after, since Linux live = measured widths).
- Driver script (1440x932): /data/s/amd-perf/scratch/picfold/picture-fold.script with floating.docx beside it.
- Left: a group already folded to its one button does not notice its content changing (its button keeps its
  width), so its stored widths refresh at the next change elsewhere or resize. Not seen in any tab.
