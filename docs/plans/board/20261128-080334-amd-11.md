# HANDOFF amd-11: W-ED-5 browser clipboard carries formatting

Landed (this PR): in the browser, copy and paste go through the system clipboard with
text, HTML and a PNG picture, not plain text only.
- Before: a paste read readText() only, so bold, tables or a picture copied from another
  app arrived as bare text; a copy wrote no picture.
- Now: a copy writes one ClipboardItem (text/plain, text/html, image/png when present); a
  paste reads all three (navigator.clipboard.read, readText fallback) and hands them to the
  app as one ClipboardData (ClipboardData(webPacked:)).
- Tests: ClipboardFormatsTests.testTheBrowsersPackedAnswerUnpacks (native);
  test/office-clipboard-web.sh in Chromium 3/3 (HTML bold pasted into Word is bold in the
  saved .docx; Word's copy offers text/html and text/plain). office-shortcuts-web.sh 8/8.
- web-drive.mjs: CLIPBOARD=1 grants the page clipboard read/write without a prompt.

Left: only Chromium tested (Firefox/Safari read permission untested). The browser web-parity
rows from the brief (Recent handle, shortcuts, print, clipboard) are now all done.
Trap: web-app.sh writes the stage last (compression takes minutes after "Build complete");
a test started before its PID exits loads a half-written app.wasm (CompileError).
