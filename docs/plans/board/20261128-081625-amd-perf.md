# HANDOFF amd-perf: U-SH-6 modal covers hide what is under them from screen readers

- Rule by property: a modal keyboard region (KeyboardRegion modal: true) now also blocks semantics, so a screen reader
  reads only the dialog or menu while it is open. That covers every dialog (DialogShell), menus and ribbon flyouts,
  and Writer's comment and note popups at once. Panes (Selection, Animation, Format) and the Find bar are not modal,
  so the document and ribbon stay readable beside them.
- Made modal where they were not: Slides' Slide Size dialog (also lets the keyboard stay inside it), the Sheets note
  editor, and the slide show (it covers the whole window).
- Test: ModalSemanticsSweepTests presses every tappable chrome control on every tab of Writer, Slides and Sheets
  (and the items of menus it opens), each from a fresh app. 99 modals, 309 other presses. A modal must expose only
  its own nodes; a full-window click-blocking cover that is not a modal region fails; otherwise the ribbon stays
  readable. About 2 minutes.
- Mac script: /data/s/amd-perf/scratch/modalsem/modal-semantics.script (marks with the Font dialog and a right-click
  menu open; no VoiceOver needed).
- Left: nothing known.
