# HANDOFF amd-6: Shape Styles saved as PowerPoint saves them (S-SH-4 follow-up)

PowerPoint lab round 1 (lab/shape-styles/shape-styles.pptx) found two faults: PowerPoint did not recognise our saved Shape Styles (ShapeStyle 0 on all 8), and a shape whose fill was edited after styling kept the OLD accent outline after a theme change.

Cause: we wrote the shape's fill, line and effects explicitly beside the p:style refs. PowerPoint (checked across the corpus: 150 shapes with lnRef 2 shade 50% / fillRef 1) writes only the geometry in spPr and leaves the rest to the refs, writing only what the user overrode.

Fix:
- A styled shape saves only the refs; a fill, line or effect changed since is written as the shape's own (per property).
- Our saved theme's format scheme now holds Office's (2013+) two gradient fills and its shadow, so refs 2/3 and effect 3 draw the same in PowerPoint as here.
- A deck opened from a file takes the look from its own theme's format scheme (first master), as PowerPoint would.
- A theme change redraws each property that still shows the style (the edited fill stays, its outline follows the new accent).

Checks: 4 new/changed unit tests in ShapeQuickStyleTests. Slides sweep: all 113 matched-win decks exact; 10 decks differ from baseline-win.tsv, and the 6 worse ones render identically on a base binary built from the same main commit (older drift, not this change).
