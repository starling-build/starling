# amd-perf: U-KEY-2 keyboard-only use (handoff)

**Landed (this PR):** a sweep test (KeyboardOnlySweepTests) reaches every ribbon command of Writer, Slides and Sheets
by keyboard alone (F6, Tab, Enter) and checks what opens: every pressable control in a dialog, menu, gallery or pane
has a keyboard stop, Tab walks them all in reading order, Escape closes it, a menu gives the ring back to its button,
a new pane is reachable by F6. Last full run: 365 commands, 40 dialogs, 99 menus, 3 panes, 3 full views, 0 problems
(about 7 minutes). `KEYSWEEP_TAB="Slides/Slide Show"` runs one tab while developing.

Fixes the sweep found:
1. Closing a menu with Escape left the ring on nothing; it now goes back to the button that opened it (Flyout).
2. A ribbon font-size box being torn down while focused committed during unmount and crashed (TextBox.dispose).
3. Side panes (Writer, Slides, Sheets' PivotTable fields) were not F6 regions.
4. Big ribbon buttons took an icon glyph as their keyboard name; they now take their caption.
5. Home/Insert > Shapes gallery: every shape is a keyboard stop, named as its tooltip.
6. Effect Options (Transitions, Animations) is greyed when there are none, as in PowerPoint, instead of an empty menu.
7. A slide show started from the ribbon by keyboard ignored Escape (the ring sent the focus back to the editor).
8. Escape now closes Set Up Slide Show, the section-name dialog and Custom Shows (Cancel in Define, Close in the list);
   Esc at the rehearsal "keep the new timings?" prompt is No.

**Left:** the shape gallery scrolls, but a ring on a shape below the fold does not scroll it into view (the sdk has no
ensureVisible yet). Visible-ring check is per registrar (each draws its own); the sweep checks stops, not pixels.
Next: KeyTips (Alt; Mac Option convention), then typing/scroll performance.
