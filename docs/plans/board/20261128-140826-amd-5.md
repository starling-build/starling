# HANDOFF amd-5: W-RV-3 PR 4, text controls with placeholder text

Landed in this PR (UI):
- A click on a plain or rich text control showing its grey placeholder selects the whole placeholder (as Word).
- Typing there replaces it in the style of the text before the control and drops w:showingPlcHdr; further typing stays in
  the control.
- Emptying a text control that has a w:placeholder brings the placeholder back, grey, flagged w:showingPlcHdr, one undo
  step with the delete. Its text: what the document showed for that glossary entry, else the entry's text from the kept
  glossary part in the document's Placeholder Text style colour (808080 when the document has none).
- Tests: DocxTests.testTextControlPlaceholdersGiveWayToTyping, testTextControlPlaceholdersInTheApp (TEXTCTL1_OUT writes the
  lab files and click points). Mac script: test/scripts/writer-textcontrols.txt. Lab: lab/textctl1 (start, typed).

Left:
- Block-level (paragraph) text controls: not handled; only controls inside a paragraph.
- Controls bound to custom XML are left empty when emptied (their text is the bound value), not given the placeholder.
- After typing over a placeholder, the caret counts as inside the control until another control is typed into; a click just
  after the control at its end then still types into it.
