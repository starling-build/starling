# U-KEY-2 KeyTips: menus and Esc levels (amd-perf, HANDOFF)

What landed (PATH: ui):
- A command whose key tip opens a menu (Change Case, any ribbon dropdown or gallery flyout) now puts letters on the
  menu's items, drawn in the menu itself (KeyTipLayer moved to sdk; every showFlyout wraps its content in one).
  Menu items take their tip letters from their text (FlyoutListTile passes it as HoverButton.semanticLabel, which
  is used only for key stops, not the semantics tree).
- Esc steps back one level as in Word: menu closes (letters return to the page's commands), then the tab letters,
  then off. Previously one Esc ended everything.
- A plain command still ends the tips once it runs; a menu item's letter runs it and ends them.
- Mac: Option sends Flutter's Alt Left/Right (macOS KeyCodeMap 0x3a -> 0x200000104), so a clean Option tap shows
  the tips exactly like Alt on Windows/Linux. No Ctrl+Option (that is VoiceOver's modifier).
- Test: KeyboardTraversalTests.testKeyTipsGoIntoAMenuAndEscStepsBack (sends the Option key code itself).

Not done: Word's fixed tab letters (N for Insert, P for Layout) - ours come from the label; KeyTips in dialogs
(Word uses underlined access keys there instead). Next: performance (task 3).
