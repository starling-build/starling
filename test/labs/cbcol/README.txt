Lab cbcol -- how narrow does Word make an overfull table's first column when it holds a check box, and does tblInd narrow the room? (Linux lo5, 2026-11-02)
Background: LibreOffice's fdo63164-1 (lo-b7c1b8df, 29 pages) has tables 6.2pt indented (tblInd 124), grid 616/2150/4936/2023 = 9725 twips against a 9071-twip text width (A4, left 1701, right 1134), auto layout, cell margins 108, no borders. The first column holds a legacy FORMCHECKBOX form field. Word shrinks the columns to fit; the lab ovfit gave the rule (each column gives up over x (w - min) / sum(w - min)) but not the check-box column's minimum, and not whether tblInd shrinks the room. Our output has that column ~16pt where Word's is ~21.6pt.
Every document: A4, margins as above, Arial 11, no compat setting, a two-row table with BORDERS (single) so the column edges can be read off the print.
Names: orig-chk = the corpus table (check box in column 1); -ind0/-ind124/-ind300 = tblInd twips; empty = column 1 holds an empty paragraph; X / M6 / M10 = column 1 holds the text X / MMMMMM / MMMMMMMMMM (centred); chk22 = check box with an explicit size 11pt instead of auto; chk-fits = grid 8789 twips (fits, nothing to shrink).
usage: build.py OUTDIR regenerates docx/. Print each with Word for Windows exactly as the corpus prints are made, then analyze.py PDF-or-DIR > table. Send the table on the branch (CBCOL-WORD.tsv).
What matters: the column edges of each table: the width of column 1 in each variant, and whether the whole table's right edge moves with tblInd.
