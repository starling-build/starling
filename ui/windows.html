Starling on Windows

A faster shell for the desktop you already run.

Dock, Start, desktop, tray — Starling replaces the Windows 11 shell itself, registered per user with no administrator anywhere, and Explorer comes back the moment you ask. Below: the three things you do most, filmed side by side on the same machine, each shell registered as the shell when it is filmed.

Faster to Start

The Start menu is finished at 67 ms — in the frame it first appears — where Windows 11's settles at 300 ms. Every number on this page is a median of 20 warm runs, filmed on the same machine at matched capture.

1 process

The whole chrome, one process

Dock, Start, desktop and file manager are one binary and one process — the launcher is a layer of the dock's own widget tree, the desktop a second engine view, the file manager a window of the same process that opens with no process start at all.

0 admin

Per-user, and reversible

The shell registration is a per-user value: one account opts in, every other account keeps Explorer, and nothing touches Program Files or a service. Uninstall — or one command — and Explorer is back at your next sign-in.

The shell

The parts of Windows you touch, replaced

Starling takes over the session the way Explorer does — Winlogon starts it as the shell — and stands in for the pieces you actually use: the dock with your pinned and running apps, a Start menu that searches everything the real one lists, the desktop with your wallpaper and icons, the system tray with quick settings and notifications, banners, and the Run dialog. Maximized windows stop at the dock's edge; minimized windows park off screen and come back from the dock, exactly as they do under Explorer.

The apps keep working, including the awkward ones: Store apps of the CoreWindow generation — Calculator, Settings, Paint, the Store itself — launch, draw and minimize correctly, because Starling keeps a background Explorer alive as a service for the plumbing only they need, while making sure it never shows a taskbar, a desktop, or any chrome of its own. Your startup apps run at sign-in in Explorer's documented order, RunOnce semantics included.

Resilience

Built to take a punch

A shell is the one program on the machine that is not allowed to leave. Starling's chrome refuses polite close requests — a stray Alt+F4, anything posting a close at the shell's window — the way Explorer's taskbar does, and writes down who tried. A supervisor restarts a crashed chrome in seconds, records the exit code, and keeps the dying run's log. And if restarting ever stops helping, the supervisor hands the machine back: it unregisters itself and starts Explorer, so the worst case of a bad day is the stock desktop, never a black screen.

This is tested by attack, not by hope: the shipping gate is 17 checks on real hardware, and the last six are hostile — closes posted at every shell window, a second shell told to stand down, and the chrome killed outright while the gate times its return and audits the forensics the death left behind.

Get started

Try it, and how to get back out

Install, per user

no administrator, nothing outside your profile
The installer copies the shell into your profile and writes one per-user registry value. It takes effect at your next sign-in; add -Now to switch this session.
powershell -File Install.ps1        # register for this user
powershell -File Install.ps1 -Now   # and switch right now

Leave

Explorer returns at the next sign-in
powershell -File Uninstall.ps1
# or just unregister, keeping the files:
WinShellBar.exe --unregister-shell

Build it yourself

Windows 10/11 x86_64 · Swift 6.2
The shell is one SwiftPM product in the open repository. The getting-started page walks the Windows toolchain setup; then:
sdk\tools\build-windows.ps1 -Product WinShellBar -Configuration release

Starling on Windows is a preview: it is the shell the numbers above were measured on, and it is developed and tested as a daily driver, but it is younger than the Linux desktop it grew from. The films' full frame-by-frame data, the capture rig, and every measurement script live in the repository beside the code.
